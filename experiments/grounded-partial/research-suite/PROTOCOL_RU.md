# Research suite: отдельные механизмы, frozen80

Зафиксировано до оценки результатов. Production runtime и frozen gold остаются прежними; базовый конечный score 33/48. Ветка experiment/semantic-selection-h1, исследовательский PR188.

1. XProvence: naver/xprovence-reranker-bgem3-v2 f2798d357213c40164bdd79557d6d2e43ca7d8d2, исходная реализация, явный threshold=0.3, title=None, always_select_title=False. Один и тот же H1 pool701; сравнить неизменённые исходные spans и сохранённые предложения, coverage до/после и стоимость. Дополнительный контроль на top5: ранжирование той же XProvence без/с pruning. Не склеивать несмежные предложения в ложную непрерывную цитату; сохранять исходные координаты. Provenсe проверяется через его многоязычное развитие XProvence; отдельные английские веса не запускаются.
2. Late Chunking: jinaai/jina-embeddings-v3 ab036b023d30b4d1138c4c3bfa9f0c445ab455d6, code bd55a5ec8e6c0fb1d6c26efb4b6a4a74ce8a88d3. Сравнить mean pooling одинаковых353 index children при отдельном encoding и при encoding целого документа (максимум8192 токена). Query/passage adapters одинаковы между вариантами. Если документ длиннее окна — явные token windows с координатами; не выкидывать хвост молча. Счёт cosine similarity; top5 primary, top1/3/10/20 diagnostic. Раздельно RU/EN.
3. Contextual Retrieval: вопрос-независимые описания353 chunks на основе полного исходного документа, локальная Qwen2.5-1.5B-Instruct 989aa7980e4cf806f80c7fef2b1adb7bc71aa306. Greedy, max128 new tokens, prompt50–80 слов. Это локальная реализация принципа Anthropic, не точное воспроизведение их модели/benchmarks. Использовать cached document prefix только как вычислительную оптимизацию. Сравнить contextual vs plain embeddings той же Jina; отдельно lexical BM25 и hybrid RRF(k=60) с теми же вариантами текста. Генерируемые описания используются только в индексе, никогда как источник доказательств. Эталонные вопросы и ответы preprocessing-модель не получает.
4. Sufficient Context: единая оценка достаточности по неизменённым witnesses на всех стадиях плюс partial/ambiguous/unanswerable/over-budget controls. Это применение методологии, не запуск авторского LLM autorater или генератора ответов. Не называть retrieval coverage улучшением конечного агента.

Все входы в модели очищены от cases IDs, answerability и witnesses. Индексирование353 оригинальных children вместо H1 pool — отдельный discovery experiment, не идентичный H1 candidate pool. Параметры не подбираются по frozen48. Сравнивать wins/losses, maximum discoverable coverage, сохранение прежних33, passage payload budget ≤800 и mapping audit. При наличии пригодных цитируемых результатов прогнать обычный projector replay с исходными checks; назвать его replay, не native integration. Любые source-only bounded packet diagnostics помечать отдельно: они не доказывают безопасный admission.

Holdout20 ранее заморожен. Использовать только для одного варианта, если frozen replay даст прирост без потери прежних33 и без нарушений. Если критерия нет, сохранить holdout нетронутым. Слабую/живую модель-генератор ответов не тестировать. Веса не публиковать; лицензии и локальную стоимость учитывать перед любым будущим внедрением.

Границы: модель preprocessing меньше модели авторов; ошибки её описаний — ограничение опыта. XProvence обучалась на абзацах, декодирование может менять пробелы; исследовать оригинальные spans, а не доверять переформатированному коду. Не объявлять ни один метод гарантией48/48.
