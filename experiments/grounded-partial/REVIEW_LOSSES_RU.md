# Ревью и исправление потерь фрагментов

Проверенный runtime: `4c6cc05`. Сравнение — с PR #187 на `c7ab9da`.
Полный прежний план не объявляется завершённым: этот проход закрывает
воспроизводимые потери на cap/qualification/ranking/projection и повторные source spans.
Слабая модель не запускалась по указанию пользователя.

## Что исправлено и почему

1. **Повторные строки через разные source URI.** Reference host раньше замечал
   повтор URI или всего текста, но принимал пересекающиеся диапазоны одного
   файла. Теперь учитываются исходные цитаты и принятые диапазоны. Пересечение
   отклоняется как `repeated_source_span`. URI не разрешает новую область;
   лимит остаётся 2 чтения по 600 admission tokens. Начальные citation hashes
   относятся к snippets, поэтому их нельзя ошибочно считать file snapshot hashes.
2. **Потеря внутри квоты источника.** В Q06 таблица с `scope="project"` была
   в pre-cap pool, но уступала менее полезным фрагментам того же документа.
   Для project-file candidates выбираются более содержательные совпадения
   внутри позиций этого источника. Межисточниковый порядок, квота и ограниченный
   structural overflow сохраняются. Ни имя файла, ни текст конкретного вопроса
   не зашиты в алгоритм. Контрпример использует независимую таблицу storage retention.
3. **Потеря при проверке словоформ.** `retried` не совпадало с `retry`, поэтому
   найденная инструкция не проходила видимую квалификацию. Добавлена регулярная
   форма прошедшего времени consonant-y: также проверены copy/copied и
   supply/supplied. Для exact identifiers преобразование запрещено.
4. **Разные требования к одному lookup в разных маршрутах.** Independent probes
   могли забывать технический anchor, который прямой маршрут требовал. Теперь
   оба учитывают typed exact terms и documentation technical anchors. Контрпример:
   вопрос про task ID у `enqueue_task` не подтверждается текстом без ID.
5. **Нужная процедура проигрывала совпадению с перефразировкой.** Среди кандидатов
   для outstanding host lookups добавлен приоритет слов исходного вопроса
   в видимом тексте с учётом частоты по различным источникам candidate pool.
   Это ранжирование, не доказательство ответа. Обязательные компоненты, exact
   identities, policy, requalification и итоговый token budget сохраняют свои роли.
   Код ранжирования вынесен из 999-строчного projector в небольшой соседний модуль.

6. **Бонус заголовка вытеснял более полный текст того же источника.**
   В `pydantic-01` вводный фрагмент проходил cap и qualification, но исчезал
   между query window и projector inputs. Для одинаковых публичных направлений
   строгое включение body matches теперь имеет приоритет над этим бонусом.
   Другой источник, отдельный lookup и несравнимые совпадения не переставляются.
7. **Частичный ответ зависел от маршрута обнаружения.** У найденного только
   через hint фрагмента могло не быть trace исходного вопроса. Проверка
   `has_context_hint_support` из-за этого отвергала полезный текст. Теперь
   body facts пересчитываются, не добавляя qualified query ids и не объявляя
   полноту. Исходная цитата `pydantic-07` сохранена. При упаковке такого
   частичного контекста более полный набор body matches внутри одного источника
   также не вытесняется повторными hints: восстановлен `typer-03` с `Aborted!`.
   Контрпример использует другой домен — отмену задания и сигнал STOPPED,
   с ограничением полного DTO в 400 tokens.

Для Q12 теперь видна последовательность `docs_status(job_id)` → успешная
подготовка → повтор исходного вопроса. Для Q06 видна таблица областей поиска.
Оба восстановления подтверждены в **guided** режиме с прежними host lookups.
Без lookups эти два вопроса пока не исправлены.

## Отброшенные варианты и самокритика

- Общее применение нового приоритета к запросам без host lookups потеряло
  предложение про parent/adjacent hydration в Q20. В финале изменение ограничено
  outstanding host directions; Q20 сохранён.
- Более широкое преобразование форм на `-ies` увеличивало совпадения, но вытесняло
  обязательный свидетель в `v2-natural-evidence-selection`. Этот вариант отвергнут;
  сохранено только подтверждённое исправление прошедшего времени. V2 снова зелёный.
- Попытка оценивать все варианты по полному родительскому тексту восстанавливала
  Q20, но снова теряла polling в Q12. Она также отвергнута: оценка видимого текста
  не должна подменяться невидимым содержимым.
- Промежуточный результат 32/48 скрывал обмен **+2 успешных случая / −1 прежний**.
  Поэтому агрегат не принят как достаточное доказательство: baseline повторён
  на отдельном worktree исходного коммита, сравнение сохранено для всех 80 cases
  и каждого ранее подтверждённого claim. В финале этого обмена нет.
- Сохранение первого кандидата до cap не решало потерю Pydantic и ломало direct
  Q05. Этот вариант отвергнут; исправлена реальная downstream-граница.
- Добавление полезных partial candidates сначала создало один bounded selector
  gap в `typer-03`. Узкий выбор по body dominance закрыл его без beam-поиска.
  Повторный exact/simple/beam diagnostic больше не обнаруживает recovery.
- Дополнительная цитата не приравнивается к полезному ответу: Q16 и Q30 без
  lookups получили тексты, не покрывающие требование, и сохраняют оценку none.
- Ни frozen-корпус, ни вопросы, ни witness strings, ни release floors не изменялись.
  Обновлён только hash inventory добавленных behavioral tests.
- Первый полный pytest выявил также отсутствие `socksio` в восстановленном
  окружении. Зависимость установлена; финальный прогон выполнен с прежним
  kernel-запретом исходящих сетевых syscall, унаследованным дочерними процессами.

## Что в прежнем плане остаётся открытым

- `plain_term` по-прежнему может участвовать в lookup с названием `exact_anchor`.
  Этот проход не объявляет полное разделение soft lexical hints и technical
  identity завершённым. Удалять такие слова нельзя: прежние проверки показывали
  потерю полезных `pre-release` и `per-source`.
- Полный host-цикл с semantic sufficiency, разрешённым local recovery и финальным
  частичным ответом остаётся интеграционной задачей за пределами reference loop.
  Наличие `resources/read` само по себе не доказывает поведение произвольного клиента.
- Остаются retrieval misses, особенно без documentation-language lookups.
  Отсутствие нужного кандидата и потеря найденного фрагмента — разные причины.
- Live weak-model A/B/C/D исключён пользователем, а не ожидает запуска.
  Бюджет 2 × 600 остаётся стартовым потолком, не доказанным оптимумом.
