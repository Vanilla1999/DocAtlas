# Implementation clarifications, before H1 score evaluation

2026-09-13. No ranking result has yet been evaluated or used to tune the model.

- Capture uses `_retrieval_stage_diagnostics`: all case candidates still exist before the service's final cap/budget loop. Earlier dispatcher retrieval limits and the existing qualified-first stable sort already happened. This is the selected baseline boundary, not an exhaustive index pool. Source-policy checks are re-evaluated for the original query on copies, without mutating production inputs. There were zero policy-rejected rows in the 80-case fixture.
- Complete set coverage is evaluated by union of literal source character spans, bound to path and recorded line range. Whitespace between source characters is ignored; text is never synthesized. This handles facts split across children without changing the frozen public-DTO evaluator. The unit is annotated witness parts, not an automatically inferred count of semantic facts.
- Step 3 uses the actual native handler with cached semantic scores rather than reconstructing a projector input from earlier candidates. Only the existing candidate list is sorted at the capture boundary. A is the already reproduced unchanged native baseline. New auxiliary calls are allowed; any unscored candidates are retained last and reported. If these occur, native results are diagnostic and not an identical-pool causal estimate. H1's standalone A/B comparison always uses the identical frozen pool.
- Scorer input includes version from the source manifest. The initial exporter used the case version field, which is identical on every frozen case; it has been changed to obtain the same value directly from the manifest. Input bytes must remain identical. No answerability, source witnesses or case ID is passed to the scorer.
- The holdout uses two new projects (Requests and Click) with pinned, byte-preserved RST sources. Its full-document reproduction controls are explicit artificial budget stress tests. Source format differs from the initial Markdown corpus and must be reported, not silently converted to improve results.
- Model inference: CPU float32, 4 threads, batch 4, 1024 tokens, default pretrained weights and raw logits. Warm timing excludes first question; model load and first question are separate. No end-to-end live model or task-token experiment.
