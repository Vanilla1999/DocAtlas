# Продолжение review: две восстановленные потери и оставшиеся ограничения

Продолжение восстановило **два полных ответа на новых вопросах**: поведение reader
при изменении исходного файла и изоляцию документации разных проектов. Это не
означает, что все прежние потери устранены. PR остаётся draft до закрытия
оставшихся задач; слабая или другая live-модель не запускалась.

Runtime этого прохода: `266a3c40cee896522a11c89f4cacda8f12275d59`.
Нативные 240 вызовов выполнены на `3ac2b7f`; последующее изменение ranking
проверено на тех же 240 projector inputs: все упорядоченные пары path/snippet
совпали. Реальный public-handler тест, который требовал последнего исправления,
также повторён. Финальные pytest, gates и systemic проверяются отдельно на
runtime-коммите. Полные публичные payloads, ручные оценки, контрольные хеши,
изменённые цитаты и история отклонённых попыток — `continued_loss_retest.json`.

## Что изменено

1. **Названное событие сохраняется при отборе.** Для ограниченной формы
   `What happens when/if ...` предпочтение учитывает слова самого события, а не
   только общую тему инструкции. Теперь новый Q17 получает:
   `A changed snapshot returns source_changed` и запрет незаметно открыть последнюю
   версию файла. Квалификация, полномочия источника и лимит DTO не ослаблены.
2. **Обычное множественное число не теряет body match.** Для неточных слов
   поддержаны формы consonant-y: `identity/identities`, `policy/policies`,
   `dependency/dependencies`. Пять новых положительных контрпримеров сначала
   падали. Точные идентификаторы по-прежнему требуют точного совпадения.
   Новый Q23 теперь получает правило отдельного project identity и изолированного
   состояния индекса, вместо пустой выдачи.
3. **Проверка независимых lookups — ограниченный fallback.** Если весь pool
   остался неквалифицированным, перед отсечением окна можно проверить уже
   найденные тела по независимым host lookups. Нового retrieval вызова нет,
   чужой BM25 score не переносится, original/parent coverage не выводится.
   Если в pool уже есть квалифицированные кандидаты, этот fallback не применяется.
   Projector продолжает повторную проверку видимого текста.
4. **Сравнение сохраняет названную операцию.** Существующий domain comparison
   frame помогает предпочесть явно названное действие его общим существительным.
   Это исправило регрессию живого теста `v2-natural-evidence-selection` после
   добавления множественного числа. Frozen witness и ожидание теста не менялись.
5. Внутренняя диагностика выводит `qualification_reason`, вместо ложного
   `unclassified` при уже известном отказе.

Это предпочтения отбора среди допустимых кандидатов, не сертификат логической
связи или полного ответа. Совпадение слов события само по себе не доказывает
причинность. Поддержка ограниченных английских форм не является общим решением
русско-английского семантического поиска.

исходящей сети; измерения не включают генерацию ответа моделью.

Два восстановленных ответа из реально выданного текста:

- **Файл изменился перед дочитыванием:** reader возвращает `source_changed`,
  не подменяет исходный snapshot последней версией. Источник:
  `docs/source-continuation.md`.
- **В двух проектах одинаковый README:** изоляция использует project identity
  и отдельное состояние индекса/извлечённых артефактов. Документы другого
  репозитория не должны удовлетворять запрос этого проекта. Источник:
  `wiki/Architecture.md`.

Это ручная незаслеплённая оценка достаточности evidence. Набор уже используется
для исправлений и повторной проверки, поэтому он не hidden holdout. Guided
lookup написан человеком; его результат не доказывает, что слабая модель сама
выберет такое перефразирование. Отрицательные контроли не доказывают отсутствие
будущих hallucinations: посторонний текст иногда всё ещё выдаётся.

Удалённый CI проверяется на публикуемом SHA отдельно. Локальные результаты
не подменяют удалённую проверку. CPU/latency сохранены как диагностика;
параллельные прогоны не используются для performance claims.

## Почему отклонены промежуточные варианты

Безусловная cross-lane квалификация (`281cc99`) прошла полный pytest, но потеряла
уже нужный фрагмент структурного overflow в старом Q22. Эту версию не опубликовали.
Ограничение fallback целиком неквалифицированным pool сохранило прежний ответ;
есть отдельный контрпример, что существующий qualified pool не вытесняется.

После исправления множественного числа (`3ac2b7f`) доменная инструкция стала
правильно квалифицироваться, но заняла один из трёх слотов и вытеснила правило
проверки обязательного доказательства. Нативный регрессионный тест это обнаружил.
Исправлен отбор названной операции сравнения, а не тест или допустимая цитата.

Таким образом, ни рост recall, ни зелёный suite в отдельности не доказывают
сохранение нужных фрагментов. Здесь проверялись и старые полноценные ответы,
и реальный пример, сломанный новым кандидатом. Простое увеличение бюджета или
замена всего selector для этого прохода не требовались.
