# Итог доработки и повторных вопросов

Инженерные доработки этого прохода завершены и проверены. Утверждение «все
потери фрагментов устранены» **по новым вопросам неверно**. Ветка стала надёжнее
в проверенных механизмах, но остаются конкретные misses и потери, перечисленные
ниже. Это не основание обещать всегда удовлетворительный ответ или сливать
ветку под видом полной продуктовой готовности.

Retrieval runtime: `43cc61b`; host adapter с финальным handoff: `4089f18`.
Слабая модель не запускалась по указанию пользователя. Все runtime проверки —
без provider, с kernel-запретом исходящих сетевых syscall у дочерних процессов.

## Что закрыто

- `plain_term` больше не получает публичную exact-identity роль. Составные
  обычные слова сохраняют foreground lexical lookup без сертификации вопроса.
  Точные команды, пути и идентификаторы сохраняют прежнюю защиту.
- Частичные hints включаются после неудачного admission основного пакета, а не
  блокируются наличием большого raw-кандидата. Они также не занимают бюджет
  у сохранившегося основного ответа. Проверено на нейтральном контрпримере и
  исходном Q11: определения exact / declared-only / unbound снова все видимы.
- Один host lookup может сохранить второй квалифицированный body-фрагмент,
  добавляющий два запрошенных термина. Это предпочтение отбора, не semantic
  proof. Новый Q04 вернул таблицу `scope="all"`; primary DTO остаётся ≤800.
  Контрпример storage compression падал до изменения и проходит после него.
  Replay на тех же projector inputs полностью совпал с последующим native run.
- Добавлен `GroundedMCPSession` поверх MCP ClientSession: одна исходная просьба,
  привязанные к цитатам host judgments, async resources/read, сохранение известного
  при неудаче, один разрешённый read-only recovery callback и общий потолок
  двух дополнительных действий по 600. Исчерпанный бюджет больше не оставляет
  невыполнимую recovery-рекомендацию. Локатор сам по себе не вызывает чтение.
- Реальный installed-artifact MCP stdio smoke использует этот adapter, включая
  text-only OpenCode registration. Это проверка транспорта и упаковки, а не
  запуск модели OpenCode. Arbitrary host должен подключить adapter; MCP resource
  сам не устанавливает поведенческий цикл во всех клиентах.

## 40 новых формулировок

120 новых вызовов public handler, 0 handler/audit errors, 12/12 native controls,
максимальный полный DTO — 800. На 36 обычных вопросах:

| Режим | Full | Partial | None |
|---|---:|---:|---:|
| Без lookup: minimal / all | 10 | 5 | 21 |
| Один lookup на языке документации | 21 | 6 | 9 |

Четыре отрицательных контроля учитываются отдельно: обещания 50% экономии,
универсальной правильности, частный пароль и обязательное 90-дневное хранение
не подтверждены. Иногда для них выдаётся посторонний текст; это не полезный
ответ и не доказательство отсутствия hallucination у будущей модели.

Это моя ручная, незаслеплённая оценка evidence, **не ответы слабой модели**.
Вопросы зафиксированы до первого запуска. Затем Q04 использован для одного
исправления, поэтому финальный набор — development/retest, не hidden holdout.
Guided lookup написан заранее человеком, без golden paths в запросе. Его выигрыш
нельзя приписывать способности слабой модели самостоятельно перефразировать.

Полные вопросы, ответы, пробелы и пути — `FOLLOWUP40_ANSWERS_RU.md`.
Публичные payloads и оценки — `finish_new40.json`; изменения после первой

## Что показали трассы оставшихся потерь

| Новый вопрос | Последняя наблюдаемая граница нужного текста | Вывод |
|---|---|---|
| Q04, scope=all | Теперь final | Исправлено: второй квалифицированный фрагмент одного lookup больше не отбрасывается безусловно. |
| Q05, scope=project; Q14, metadata budget | Есть в query window, нет в projector context pack | Потеря до projector; нужна разборка сборки/квалификации context pack, не увеличение output budget. |
| Q15, отсутствие автоматического I/O | Есть в qualified variants, нет в final | Полезное правило проигрывает другим совпадениям. |
| Q17, source_changed | Есть в qualified variants, нет в final | Общее lifecycle/sync вытесняет конкретное условие reader; raw retrieval уже нашёл факт. |
| Q23, project isolation | Есть после cap, нет в query window | Потеря при ограничении окна запроса. |
| Q25, per-source; Q35, agent-contract | Есть в projector inputs, нет в qualified variants | Русская формулировка и слабый lookup дают мало body matches. Не решать глобальным ослаблением qualification. |
| Q36, task tokens | Есть в индексе, нет в pre-cap | На этом запросе промах discovery. Selector не может выбрать отсутствующего кандидата. |

Это локализация по конкретным текстовым маркерам, не автоматическое доказательство
семантики. Полные target candidates, qualification traces и счётчики этапов —
`finish_loss_diagnostics.json`. Счётчики могут повторять один span в разных calls.

Отдельно найдены устаревшие/внутренние инструкции: новый Q02 возвращает старый
`sync_project_docs` как прямой tool; Q11 без lookup — `get_docs_job_status` из
архитектурного описания. Их нельзя механически превращать в публичные MCP вызовы.
Текущий schema и canonical three-tool contract имеют приоритет. Выдача Q17 и
Q22 даже помечена `retrieval_coverage=full`, хотя нужного ответа в ней нет:
покрытие retrieval-направлений не равно покрытию фактов.

## Проверка идеи «дадим ссылку»

Два дополнительных post-hoc опыта через production reader и host adapter:

- Q16: **1 чтение** дало правило проверки identity/catalog/snapshot; host завершил
  ответ. Это не сертификат сервера: `answer_supported` остаётся false.
- Q15: **2 чтения** выбранного источника не нашли инструкцию выше исходной цитаты.
  Continuation идёт вперёд. Известный способ работы с локатором сохранён; итог
  partial с `read_budget_exhausted`, без бесконечного расширения контекста.

Записаны полные результаты: `finish_source_reads.json`. Выбор был ручным;
опыты не оценивают среднюю вероятность успеха reader. 2×600 — ограничитель
дополнительного evidence, не оптимум и не общий task-token budget.

## Критика собственного вывода

Было бы ошибкой сказать, что проблемы теперь только в языке запроса: Q15/Q17
доходят до qualified variants и теряются позже. Было бы также ошибкой заменить
это сложным selector: bounded systemic diagnostic не показал выигрыша, а пробная
перестановка ranking меняла много ответов и не восстановила snapshot-правило.
Она отклонена. Наконец, добавление host-документа увеличило корпус: его эффект
на новых вопросах нельзя выдавать за чистый runtime-выигрыш.

Инженерный контракт стал надёжнее, но продуктовая задача ещё не закрыта целиком.
Ни зелёный CI, ни хороший guided lookup, ни доступный URI не гарантируют успешную
семантическую оценку у произвольного клиента. Live weak-model experiment исключён,
а не скрыто считается пройденным.

## Следующие ограниченные задачи для исполнителя

1. **Согласовать maintained docs с публичным schema.** Убрать stale direct-tool
   примеры; отдельно обозначить внутренние service methods. Проверять примеры
   по advertised tool inventory. Не менять frozen witnesses ради pass: сохранить
   исторический corpus отдельно от обновляемых документов и повторить обе проверки.
2. **Добавить reasons на каждый discard между query window и context pack.**
   Воспроизвести Q05/Q14 и независимые контрпримеры. Не снимать source policy,
   exact identity или body qualification. Pass: нужный квалифицируемый span
   доходит дальше либо имеется конкретный корректный refusal reason.
3. **Сохранять запрошенное условие в final selection.** Для Q15/Q17 проверить
   границы obligation/candidate/visible snippet на одном зафиксированном pool;
   построить другие примеры «действие при условии». Не раздавать original-query
   coverage за общий sync alias. Требовать отсутствие потерь прежних full.
4. **Разобрать query window и недостаточный language lookup отдельно.** Q23 —
   окно; Q25/Q35 — недостаточная квалификация. Не зашивать русский вопрос,
   golden path или ответ в production. Проверять новые RU/EN формулировки и
   сохранять исходный вопрос вместе с необязательным lookup.
5. **Измерить bounded чтение около anchor, включая предыдущий фрагмент.**
   Сначала контракт и контрпример Q15; сохранить opaque locator, project/snapshot
   policy, общий 2×600 и отсутствие авто-чтения. Не открывать весь файл ради уверенности.

Эти задачи сформулированы по новым наблюдениям и не заявлены реализованными.
До их проверки PR остаётся draft; утверждение «оставшихся потерь больше нет»
не соответствует измерениям.
