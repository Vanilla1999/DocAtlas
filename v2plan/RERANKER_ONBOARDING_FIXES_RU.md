# Исправления Qwen-onboarding после release review — 2026-11-13

База PR: `main` / `89af562a7848cb003ed849467f1f61738957362b`.
Вариант A сохранён: Qwen остаётся экспериментальным opt-in, без лексического
fallback и без изменения модели, SHA-256 ассетов, runtime-пинов или формул отбора.
Этот PR не является разрешением на релиз, смену версии или merge.

## Что исправлено

- `prepare` пишет в собственный приватный staging, проверяет все пины и только
  затем публикует каталог. Очистка ошибки/Ctrl-C не удаляет пользовательский
  destination. Symlink, непустой путь и изменение destination отклоняются.
- Preflight и runtime переиспользуют одни и те же проверки конфигурации.
  JSON отдельно сообщает assets/runtime/profile, включён ли Qwen, и что
  model load/inference/request binding не проверялись. При включённом профиле
  явный аргумент `check DIR` не может скрыть неправильный активный model path.
- Paired Qwen + minimal отклоняется до проверки ненужной minimal-модели.
  Paired Qwen + MiniLM section compression больше не может незаметно выбрать
  другой scorer. Оба конфликта имеют публичный MCP reason_code и подсказки.
- Qwen-инструкция явно задаёт `DOCATLAS_CONTEXT_COMPRESSION=off`, учитывая
  неявную активацию MiniLM через унаследованный `DOCATLAS_MINILM_MODEL_DIR`.
- Установка сохраняет PyPI и добавляет именованный PyTorch/cu128 index.
  Подсказка установки выводится для несовпадения зависимостей, а не как
  универсальное исправление файлов модели или неподдерживаемой GPU.
- Уточнены capability 12.0, смысл `torch==2.10.0`, возврат к lexical default,
  различие окружения терминала/MCP и сравнение стоимости с paired Qwen R−D,
  а не с непроверенным лексическим baseline.
- В platform-smoke добавлены установленные CLI/MCP интеграционные сценарии.
  Старый stdio smoke и его критерии не удалены и не ослаблены.

### Что подтверждено конечным результатом

- Default doctor не требует опциональную модель. Неверный mode, paired/minimal,
  неверный budget и активная MiniLM-компрессия видны в profile diagnostics.
- При одинаковом унаследованном MiniLM path явный compression=off снимает
  конфликт, но отсутствие Qwen-ассетов/runtime по-прежнему не даёт ready=true.
- Относительный/непустой/symlink destination отклоняется до сетевого обращения;
  ошибка транспорта сохраняет прежний пустой каталог; SIGINT сохраняет файл,
  который независимый участник создал в destination во время скачивания.
- Default MCP требует подтверждение подготовки: отказ без grant не создаёт
  store. После явного author grant доставлены **2/2** авторских факта, включая
  условие подтверждения; проверены исходный текст, строки, scope и authority.
- На том же подготовленном store конфликт Qwen/MiniLM возвращает именно
  `paired_qwen_requires_compression_off`, пригодные для действий hints и не
  выдаёт источников. SHA-256 базы не изменился. Generic bad_request или отказ
  из-за отсутствующей MiniLM-модели не засчитывались бы как PASS.

## Повторение интеграционной проверки

В среде с доступом к индексам пакетов собрать и установить проверяемый wheel
в отдельный venv, затем из checkout выполнить:

```bash
uv build
uv venv --python 3.12 .venv-onboarding
uv pip install --python .venv-onboarding/bin/python \
  dist/doc_atlas-1.3.2-py3-none-any.whl pytest
.venv-onboarding/bin/python -m pytest -q -s tests/test_reranker_onboarding.py
```

Тесты используют реальные subprocess CLI и stdio MCP. Для полной офлайн-проверки
нужен предварительно доступный tokenizer cache; существующая test fixture
подготавливает его по обычным правилам репозитория. Новый шаг CI запускает
те же сценарии после установки wheel на Linux и macOS; локальный Linux PASS
не объявляется результатом macOS.

## Что ещё необходимо для release sign-off

1. Чистый installer/uv-cache сценарий на Linux и macOS и регистрация клиентов.
2. Реальное разрешение/установка исправленной GPU-рецептуры, полный успешный
   `prepare` с доступом к HF CDN и один настоящий scoring на пиннутой GPU.
3. Разбор предсуществующего красного installed-MCP baseline: такие же отказы
   присутствуют в c5f34997 и его родителе. Этот PR не меняет их эталоны ради PASS.
4. Успешные release workflow проверки wheel/sdist из одного точного кандидата;
   отдельное утверждение номера версии/тега и публикации.

Ограничения подготовки: родительский каталог должен быть доверенным; это не
защита от злонамеренного процесса с тем же UID, заменяющего ancestor paths.
SIGKILL не позволяет выполнить cleanup. После атомарной публикации отмена
может оставить полностью проверенный результат. Пины и no-fallback сохранены.
