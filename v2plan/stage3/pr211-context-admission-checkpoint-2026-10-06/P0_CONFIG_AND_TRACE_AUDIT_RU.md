# P0: generated configs, prompts и final citation integrity

2026-10-06. Audit-only slice; product/gold не изменены.

## Generated host boundary

`mcp/agent_config.py` прочитан целиком. `known_agents` выбирает точные host paths;
`_json_server_mapping` выбирает protocol keys по explicit style, не по вопросу.
`_desired_server_entry` выдаёт фиксированную local command и environment.
`register_server` не читает question, проверяет ownership существующей command,
сливает только свою запись; TOML путь также проверяет существующий server.

Решение: **TECHNICAL-RETAIN-CANDIDATE** для config serialization/ownership,
точного host registry и `DOCATLAS_MCP_TEXT_FALLBACK`. Это не exemption для
произвольных будущих routers внутри config. Внешние user config не читались.

[Probe](p0_config_boundary_probe.py) использует только disposable directory
в `/tmp/opencode`; проверены пять styles, first write, idempotent second write,
распознавание current entry. [Report](archives/p0-config-boundaries.json)
содержит actual generated bytes/hashes.

## Prompt generation

`cli/_commands_part01.py:_get_template_content` читает packaged template,
вставляет canonical agent contract и его hash identity.
`_build_skill_content` заменяет command placeholder; `_install_skill_file`
пишет managed block с ownership markers, а не извлекает смысл question.
Rendered outputs всех Markdown templates сохранены в config probe.

Однако `mcp/agent_workflow_contract.py:WORKFLOW_POLICY` — не просто schema:
`free_form_lookup.compound_or_cross_language_decomposition_required=True`
и список `decomposition_triggers` предписывают смысловую обработку caller.
`scope_planning` связывает overview/policy/cross-module request categories со scope.
Они достижимы через rendered instructions и публичный contract identity.
Решение D33: **SPLIT**. Сохранить explicit scope authority, immutable question,
неавтоматическую preparation/recovery и запрет edit authority; синхронизировать
с optional RU/EN lookup capability в согласованной migration. Не объявлять
instructions dictionary-independent только потому, что Python не выполняет их.

`PUBLIC_EXAMPLES` содержит RU question→EN lookups, но не runtime lookup table:
`public_agent_contract` копирует examples в contract payload. Решение:
**RETAIN AS ILLUSTRATIVE DATA**, при запрете exact-question arbitration через
эти examples. Это отличается от D37: frozen questions реально используются
`evidence_requirements` для production arbitration.

Дополнительно прочитаны `_docs_server_resources.py`, `_docs_server_shared.py`,
schema/config classes и `read_docs_resource`. Probe сохраняет все восемь
admin×advanced×text-fallback surfaces, handler identities, пять static resources
и два generated workflow resources. Public descriptions выбираются explicit
tool key; fixed `.replace` меняет wording, не выполняет question interpretation.
Решение: technical protocol assembly оставить; NL category→scope/tool guidance
выделить в D33 SPLIT вместе с canonical instructions, не считать schema literals.
Static trust schema — TECHNICAL-RETAIN-CANDIDATE; source continuation URI только
по выданному reference, budgets и expiry сохранить.

Generated project/library workflows содержат legacy `mode="auto"/"library"`
и ecosystem argument, отсутствующие в advertised public get_docs_context schema.
Это отдельный instruction compatibility defect, не основание расширять scope
или молча менять tests. Привязать его к P1 instruction migration ledger.
Source templates не вычисляют commands из темы вопроса: values подставляются
из URI; контент такого resource не является authorization.

Прочитаны actual descriptions и property descriptions всех **14** tools в
admin+advanced surface (не только public fallback strings):

| Surface | Решение |
|---|---|
| `get_docs_context` | SPLIT: optional lookup/scope guidance vs immutable question и non-authorization guarantees. |
| `prepare_docs`, `docs_status`, `docs_job` | Explicit action/job protocol оставить; free-form request categorization не переносить в keyword dispatch. |
| `inspect_project_docs`, `get_code_context`, `get_patch_plan_context` | SPLIT: NL workflow/task routing; legacy inspect-first chain конфликтует с canonical get_docs_context-first guidance, requires migration. |
| `get_patch_constraints`, `validate_patch_against_constraints` | Typed workflow/integrity limitations оставить; не превращать instruction example в permission или proof. |
| `list_docs_sources`, `inspect_library_docs`, `remove_library_docs`, `prune_library_docs`, `list_library_docs` | Exact registry/admin operations и diagnostics guidance; нет question→expected answer table в descriptions. Confirmation/scope gates сохраняются. |

Наличие противоречащих instructions зафиксировано как baseline defect; восемь
surface snapshots позволяют проверить default и opt-in variants без чтения
реального user environment. Scope этого подпункта classification закрыт;
product migration и independent acceptance не выполнены.

## Same-call final projection

[Integrity runner](p0_trace_integrity.py) проверяет:

- Все passage blob references разрешаются; SHA256 каждого blob совпадает.
- Каждый final evidence ID присутствует в snapshot.
- Final row совпадает с `projected_source` snapshot.
- Исходный source digest проверен **до compaction** вызовом production
  `_source_digest`: hash включает path/section/content/snippet/version.
  Он не является hash одного final snippet.
- Snippet находится внутри заявленных final line ranges текущего source file.

[Report](archives/p0-trace-integrity.json) сохраняет checks по каждому evidence ID,
event counts, budget violations и все исходные report errors. Semantics и
релевантность этим не доказываются. Profiler timing nested, с observer overhead.
Trust probes не имеют witness gold и не заменяют positive trust acceptance.

Baseline теперь сохраняет **реальное содержимое isolated SQLite** до удаления
temporary storage: schema, sorted rows/row hashes, `index_generations.config_json`,
context/retrieval config hashes, active generation и actual retrieval config.
Все четыре lanes содержат **134 generation sources, 1433 retrieval parents,
2779 retrieval children, 1441 sections**; vector-upsert rows отсутствуют.
Для каждого из 134 indexed sources проверены content hash и точное совпадение
indexed content bytes с source file. Все проверки прошли во всех четырёх lanes.
Это больше не вывод о corpus из списка tracked files.

Все **98** final source rows проходят source digest, exact projected row после
восстановления content-addressed blobs и snippet-in-declared-lines checks.
При проверке выявлена потеря `scope` в audit-only compaction; поле добавлено,
все четыре runs повторены. Production projection не менялась.
Integrity runner возвращает nonzero при failure citation checks.
