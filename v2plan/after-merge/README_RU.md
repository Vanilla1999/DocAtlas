## Что нельзя отложить под видом улучшения

Upstream retrieval пункты ниже теперь имеют отдельную отсрочку владельца
по связанному документу; это не отменяет прочие проверки и не доказывает готовность выпуска.

- Полезные разные формулировки вопросов в поддерживаемом основном MCP-сценарии.
- Multi-section context, условия/исключения и сохранение полезных partial facts.
- Искусственные потолки docs/patch output и тихая потеря нужных данных.
- Source identity/hash/span/scope/version/freshness, consent и bounded read guards.
- Явное решение по schema/catalog ceilings и проверка поддерживаемых clients.
- Миграция старых API/assertions/gates с сохранением активных требований.
- Неизвестные причины блокирующих failures и неисполненные обязательные gates.
- Проверки установки, реального MCP delivery и итогового совместного SHA.

Не требуется восстановить механизмы старого main. Но отложенная capability
не может одновременно оставаться обещанной и непроверенной в текущем release.

## Как добавить доказанный deferred fix

Только после отдельного решения владельца: точный repro/node и SHA, ожидаемое
активное поведение, observed failure, причина допустимости отсрочки, проверенное
влияние на текущий release, scope исправления и критерий завершения. Нельзя
переносить сюда required-gate blocker без явного согласованного изменения контракта.
