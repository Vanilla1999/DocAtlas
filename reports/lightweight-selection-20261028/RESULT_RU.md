# PR #233 — повторный анализ от main, бюджет 1,5 ГБ

## Решение

Основа — main `439815771b96edc77a12f42f90f1fecb35f5e5d7`. Продуктовый код
PR #232, Qwen3-4B, Phi и цикл autorater/recovery не перенесены. Default не изменён,
PR остаётся Draft. Сам по себе зелёный measurement job не является приёмкой качества.

**Практический кандидат — MiniLM-window как узкое исправление длинных вопросов.**
На 58 вопросах он восстановил три требования, не потеряв ни одного, которое
доставлял main. Максимум всего baseline-контейнера: **608 522 240 байт**.
Это не решение общей достаточности и не новая токенная экономия.

**Qwen3-Reranker-0.6B Q4_K_M поместился: 1 295 200 256 байт на весь контейнер.**
Новых потерь относительно main нет, но существенной экономии текста тоже нет,
а задержка выросла. На V40 все 40 запросов завершились откатом по дедлайну;
это не 40 успешных решений reranker. Пока только опциональный эксперимент.

Обычный **Qwen3-0.6B Q8_0 select не принимается**: потерял значение одной явно
запрошенной версии, увеличил текст на свежем наборе и достиг предела памяти.
Пик **1 500 016 640 байт**, `memory.events:max=988`, но `oom=oom_kill=0`.
Это не OOM и не доказательство принципиального неумещения 0.6B: в данной
конфигурации нет запаса и есть содержательная регрессия.

## Какой этап меняется

Main с явно предоставленными весами использует **MiniLM + facet-guarded-lexical-v2**.
Fixed-five — отдельный rollback, не текущий default. **LiteLLM — интерфейс к
провайдерам, не используемая локальная модель MiniLM.** Новый SDK не добавлен.

Новые режимы включаются только хостом через `DOCATLAS_LIGHT_SELECTION`.
Поиск, допуск источников и последующая валидация остаются main. MiniLM-window
меняет только обработку длинного входа. Успешные Qwen-режимы заменяют выбор
разделов; после них нет дополнительного лексического вето. Модель выбирает ID,
а код передаёт оригинальные строки с scope/version/authority/instruction_trust.
`DOCATLAS_CONTEXT_COMPRESSION=off` остаётся off.

Нового ограничения 3000 токенов нет. Старая граница main на полный машинный
пакет сохранена. Контекст 2048 — рабочее окно маленькой модели, не предел
ответа платной модели. Полный раздел не режется; если все разделы обработать
невозможно, альтернативный выбор отбрасывается и используется main.

## Варианты и исследовательские основания

| Режим | Реализация | Граница доказательства |
|---|---|---|
| main | Имеющийся MiniLM и facet-guarded-lexical-v2 | Не гарантия достаточности |
| fixed-five | Существующий rollback, пять групп | Постоянное k не доказывает полноту |
| minilm-window | Все окна длинного вопроса по 128 токенов × окна текста, MaxP | Межоконные смысловые связи не гарантированы |
| qwen-rerank | Обученный Qwen3-Reranker-0.6B, native rank pooling, yes/no при 0,5 | Relevance не равен sufficiency |
| qwen-select | Qwen3-0.6B возвращает ID полных разделов | Корректные ID не гарантируют правильный выбор |

Reranker использует реально обученные для ранжирования веса из семейства
[Qwen3 Embedding/Reranker](https://arxiv.org/abs/2506.05176), а не чат с названием
статьи. Сторонняя Q4_K_M-конверсия и некалиброванный порог 0,5 — отдельные
deployment-решения. Порог не подгонялся по результатам. MiniLM-window — инженерная
MaxP-подобная абляция, chat-select — prompt-based прототип. Это не воспроизведение
обученных компрессоров RECOMP или autorater из Sufficient Context.

[LLMLingua-2](https://aclanthology.org/2024.findings-acl.57/) рассмотрен, но не
внедрён: удаление токенов требует явного контракта сохранённых spans. Нельзя
изменить выдержку и продолжать представлять её как неизменный исходный текст.
Подробный анализ вариантов: [контракт эксперимента](../../docs/lightweight-selection-15gb.md).

## Память: общая группа, не только файл весов

Одна cgroup содержит Python/DocAtlas/MCP, SQLite, тестовый клиент, MiniLM при
загрузке и не более одного Qwen-сервера. Запрошено **1 500 000 000 байт**, не
1,5 ГиБ. Linux округлил границу до **1 499 996 160**. Swap выключен; два CPU;
сеть во время запросов выключена, кроме loopback. Сборка и скачивание отдельно.

Веса загружаются через `--load-mode none` в частную память измеряемой группы:
хостовый файловый кеш не должен скрывать расход модели через mmap. Учитывается
`memory.peak` всей группы, а не размер GGUF или сумма несовпадающих RSS-пиков.

| Runtime-группа | memory.peak, байт | max / oom / oom_kill |
|---|---:|---|
| main, fixed-five, MiniLM-window последовательно | 608 522 240 | 0 / 0 / 0 |
| Qwen3-Reranker-0.6B Q4_K_M и всё остальное | 1 295 200 256 | 0 / 0 / 0 |
| Qwen3-0.6B Q8_0 и всё остальное | 1 500 016 640 | 988 / 0 / 0 |

[Kernel cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html) допускает
временное превышение memory.max в отдельных ситуациях. Сырые числа не округлены
до PASS: строгий критерий peak <= 1 500 000 000 для chat-ветки не выполнен.
Но контейнер завершился без OOM; утверждать обратное нельзя. Baseline-пик общий
для трёх последовательных режимов, не три отдельных измерения. Это измеренный
runtime данного теста, не универсальная гарантия для любого корпуса/оборудования.

## Сохранение доказательств

58 вопросов: неизменные V40 (40), известные L10 (10), новые авторские (8).
Свежий набор составлен тем же автором, не независимыми оценщиками. На V40
считаются замороженные группы свидетельств; на L10/fresh — документированные
требования. Неизвестные части не засчитываются как правильные unknown.

| Режим | V40 | L10 | Fresh | Новые потери к main |
|---|---:|---:|---:|---|
| main | 31/32 | 16/21 | 13/17 | Контроль |
| fixed-five | 32/32 | 14/21 | 10/17 | 4 L10, 3 fresh |
| MiniLM-window | 31/32 | 19/21 | 13/17 | Нет |
| Qwen select | 31/32 | 21/21 | 12/17 | LW05 / v1 |
| Qwen rerank | 31/32 | 21/21 | 13/17 | Нет |

**Это измерение цепочек вместе с fallback, не чистая оценка моделей.**
Обе Qwen-ветки применились в 2/10 L10, 8/8 fresh и 0/40 V40 — всего **10/58**.
Остальные запросы использовали прежний main. L10: восемь откатов по дедлайну;
V40: chat превышает лимит четырёх полных партий ещё до генерации, reranker
не успевает оценить весь пул за десять секунд. Частичные решения не применяются.

### Проверенные улучшения и регрессии

**L10-08:** main отказывает из-за длинного вопроса. MiniLM-window доставляет
все три требуемых правила за **1,391 с**, без дополнительной LLM. Qwen select
и rerank доставляют те же три требования за 8,56 и 8,97 с соответственно.
На других общих успешных запросах MiniLM-window сохраняет тот же текст main.

**L10-03:** main/window сохраняют два предусловия восстановления, но теряют
restore и последующий replay. Оба маленьких Qwen сохраняют все четыре требования,
но при этом оставляют весь доступный пул этого вопроса. Это полезный локальный
эффект, не доказательство минимальности или общей экономии.

**LW05:** спросили значения Moss v1 и v2. Chat-Qwen выбрал v2 (=6) и документ
о цветах, отбросив v1 (=3). Это реальная потеря, не штраф за отсутствие дубля.
Main и reranker сохранили обе версии. Валидация ID смысловую ошибку не ловит.

**V40-B07:** fixed-five восстановил BLACK_CACHE_DIR, пропущенную main, который
выдал Poetry/ESLint вместо нужного Black. Но на L10/fresh fixed-five вносит
новые потери и увеличивает общий текст. Нельзя объявлять его универсально
хуже/лучше. Он также использует legacy-группировку, поэтому это не чистое
изменение только k при одинаковых группах.

### Пробел до этапа отбора

Во fresh LW02 четыре требования восстановления отсутствуют уже в публичном
пуле до тестируемого селектора. Есть только switches.md; нужных production.md
и restore.md нет, хотя все документы индексированы. Контроль pool даёт **13/17**.
Селектор над таким пулом не может вернуть отсутствующие у него четыре факта.

Это локализует сбой до section selection, но не различает retrieval, admission
и upstream projection. Fixture работает offline с auto-vectors=0; результат
не следует переносить на все конфигурации production. Нужна отдельная трасса,
а не ещё один проверяющий поверх уже неполного набора.

## Текст для следующей модели и задержка

Сравниваются те же успешные вопросы; короткое сообщение об ошибке не экономия.
L10-08 исключён из парной оценки текста, поскольку main на нём ошибается.
Проценты ниже — изменение полного MCP-текста; плюс означает рост, не экономию.

| Вариант к main | L10: 9 общих | Fresh: 8 | V40: 40 |
|---|---:|---:|---:|
| MiniLM-window | 0% | 0% | 0% |
| Qwen select | +6,01% | +29,83% | +0,01% |
| Qwen rerank | +6,15% | -0,37% | +0,06% |
| fixed-five | -8,03% | +3,34% | +138,97% |

V40 у двух Qwen-веток содержит те же исходные source bytes main: мелкая разница
ссылок/обрамления не является эффектом отбора. -0,37% reranker на fresh — всего
26 токенов (6999 -> 6973), не доказательство значимой экономии. У window прирост
токенов на полном L10 относится к исправленному ранее ошибочному запросу.

| Режим | Медиана L10, те же 9 успехов | Fresh, 8 | V40, 40 |
|---|---:|---:|---:|
| main | 0,827 с | 0,466 с | 14,979 с |
| fixed-five | 0,527 с | 0,329 с | 8,998 с |
| MiniLM-window | 0,842 с | 0,469 с | 15,027 с |
| Qwen select | 12,315 с | 7,545 с | 16,157 с |
| Qwen rerank | 11,483 с | 7,451 с | 22,033 с |

Это одно последовательное измерение MCP на CPU, не controlled performance
benchmark и не время окончательного GPT-ответа. Модели загружены заранее.
Дедлайн альтернативы не включает retrieval/fallback. В chat server.log видны
отмены восьми timed-out задач, но это не гарантия отмены любого HTTP-сервера.

## Что подтверждено и ограничения

**470 настоящих get_docs_context-вызовов**, установленный wheel, публичная
подготовка, stdio MCP и SQLite. В основных вопросах записаны 18 chat-попыток
(10 завершены) и 486 rerank-попыток (439 завершены). Неуспешные вызовы не
маскируются успешным fallback. Исходные файлы и логическое состояние SQLite
проверены неизменными. Публичные unavailable-server и compression=off controls
прошли для обеих моделей.

Офлайн-аудит без импорта DocAtlas проверил все 470 записанных ответов, ZIP/SHA,
оригинальные spans/цитаты и provenance, заново оценил frozen witnesses и
пересчитал o200k независимым BPE. Продукт и fixtures одинаковы в сравниваемых
runs. SQLite/inference офлайн не повторялись. Gold/промпты/продукт не подгонялись
после измерений. Старые V40/L10 известны; fresh — same-author exploratory.

**Платных вызовов 0, usage=null, BLOCKED_NOT_CONFIGURED.** Окончательные ответы,
correct unknown, stock OpenCode и оплаченный полный диалог не проверялись.
MCP-токены лишь proxy; они не доказывают снижение счёта GPT. Локальные токены
не подмешиваются в финансовую оценку.

Два ранних Qwen-прогона остановились до инференса: page-aligned проверка лимита,
затем устаревший флаг --no-mmap. Исправления только harness/runtime; завершённый
baseline переиспользован. Подробности в eval/lightweight_evidence/INFRASTRUCTURE_NOTES.md.

## Дальнейшее инженерное решение

Сохранить MiniLM основной моделью, отдельно рассмотреть узкое window-исправление.
Qwen-reranker оставить исследовательским opt-in, chat-Qwen не продвигать. Не
создавать обязательный дополнительный autorater. Main не меняется.

Сначала локализовать недополучение источников до отбора, затем проверять экономию
транспорта/полного агентного диалога отдельно от достаточности. Короткий lookup
или многоязычный поиск до MiniLM — следующие гипотезы, **не реализованные и не
проверенные здесь**. В main уже есть host_lookup, сохраняющий original_question
без наследования доказанной полноты. Повтор раскрытого LW02 после настройки не
будет независимой приёмкой.
