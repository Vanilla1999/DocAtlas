# B V3: frozen client citation contract (до host calls)

Дата: 2026-10-12. Это отдельный минимальный client experiment, не изменение product DTO, V2, corpus/questions/oracle или source policy. Контракт фиксируется до любых новых host calls. Агент B не запускал runtime/model/host/tests/compile/private helpers; работоспособность исполнения пока NOT TESTED.

Исправление после `review/PREFLIGHT_REVIEW_RU.md`: **contract `citation-coordinates-v3-2`**, adapter identity `citation-adaptation-v3-2-envelope-authority-empty`. Прежний v3-1 не использовать для inference: его snippet-hash предположение было неверным. Новый identity включён в prepared/extraction и проверяется extractor. Координатор обязан до inference зафиксировать SHA256 фактических bytes исправленного adapter/report/prompt и prepared/model messages; symbolic identity и prepared hash не заменяют file hash или подпись доверенного producer. Static re-review C ещё требуется отдельно; исправление не объявляется PASS.

## Новый generator output

`citation_adaptation.py` экспортирует `GENERATOR_PROMPT_RU`. Координатор передаёт его как новый system prompt, а `prepare_packet(public_result, binding)["model_input"]` как JSON user input. Исходный вопрос берётся без изменения из public result. Это **новый generator contract**, не исправление старого ответа и не apples-to-apples сравнение со старым prompt без отдельной маркировки.

Строго один JSON object без Markdown fences:

```json
{"status":"complete","claims":[{"claim":"Утверждение","citations":[{"source_id":"ev-ID","start":0,"end":42}]}],"missing":[]}
```

`status`: `complete|partial|insufficient`; `claims`: отдельные существенные утверждения; каждое требует непустой список citations. `missing`: список строк. `insufficient` требует пустые claims; `partial` и `insufficient` требуют непустые missing. `complete` требует непустые claims и пустые missing. Никакого отдельного свободного answer или сгенерированной quote: ответ — именно исходные claims. Диапазон `[start,end)` задаётся в Unicode code points относительно **точного публичного snippet**, нулевая база; bool/float не являются offset. Model input содержит исходный text, его длину/hash и вспомогательные точные snippet-relative строки с диапазонами. Строки не являются новыми источниками.

Не угадывать координаты, не склеивать несмежные диапазоны, не удалять Markdown/пробелы/newline, не подменять отрицания/условия/стороны сравнения. Для нескольких фрагментов перечислить несколько citations. Если координаты или поддержка неизвестны — missing, а не реконструкция фактов. Извлечение не принимает quote и не ищет похожий текст. Новые host calls, лимиты, paired design и freeze hashes prompt/adapter/model_input/sidecar — ответственность координатора; импорт адаптера ничего не исполняет.

## Binding и граница извлечения

Только существующие `payload.sources` по evidence_id; pool, read_next и другие невыданные источники недоступны. Используется сохранённый sidecar `validation_snapshot` того же public call, без вызова внутренних product helpers. Требуется EXECUTED, пустые integrity_errors, неизменное state_before/state_after и **все три** `answer_supported`, `answer_available`, `edit_ready` строго false (пропуск поля также блокирует). Вся projected_source должна совпадать с public source. В текущем минимальном варианте snippet должен **целиком равняться** reference text/raw_document[char_start:char_end]; составной, обрезанный или неоднозначно связанный snippet отклоняется, а не выравнивается поиском. Binding задаёт project identity (V2 local SHA256 пути project), generation, project/unversioned и allowlist document_hashes. Synthetic domain_version не становится product version.

Hash полного UTF-8 документа проверяется по reference source и allowlist binding. **Public `content_sha256` — не snippet SHA**, а SHA256 canonical JSON envelope из сохранённого `validation_snapshot[ID]["source"]`. Статически сверенная production schema: `_model_visible_docs_support.py:42–50`, serializer `model_visible_projection_helpers.py:197–198`, validation `model_visible_projection.py:744–750`. Поля/порядок fallback operands (Python `or`, без trim, без преобразования значений): `path=path|source|url|source_url`, `section=heading_path|title`, `content=content|display_text`, `snippet=snippet|code`, `version=version_binding|version|requested_version`. Все пять ключей присутствуют, включая null. Сериализация: `json.dumps(envelope, ensure_ascii=False, sort_keys=True, separators=(",", ":")).encode("utf-8")`. Adapter воспроизводит только эту client schema, не импортирует/вызывает product helper и не вычисляет envelope из projected snippet/path/section. Public hash должен совпасть с этим digest и неизменённым projected_source. Envelope operands/digest сохраняются в client sidecar для review; отдельный `text_sha256` — только client hash точного snippet. Packet и его hashes не переписываются.

Это проверка сохранённого snapshot, не повторная live validation и не доказательство текущих ACL/consent/version-denial. `integrity_errors=[]` является утверждением producer; проверка envelope не доказывает остальные source-policy/parent-line/catalog operands. Reviewer независимо проверяет сохранённые source/state/catalog bindings; произвольная user-created запись не становится validated public packet. Весь документ и envelope не передаются модели. Sidecar нужен только extractor/reviewer.

Явный `sources=null` или `sources=[]` допустим: model input получает пустой список sources, sidecar — пустые fragments, без fabrication. Отсутствующий ключ или тип, отличный от list/null, блокирует подготовку. На пустом packet только `insufficient` с пустыми claims и непустыми missing может пройти extraction; complete/partial с citations не разрешатся. Это не доказательство, что отказ честный, и не rescue пустого positive: для заранее выбранного positive координатор фиксирует empty/PREPARE_BLOCKED/NOT_RUN согласно workload, не заменяет case и не объявляет citation PASS.

Извлекается `snippet[start:end]`; одновременно сверяется точное равенство исходному raw_document по абсолютным code-point координатам. Hash quote — SHA256 UTF-8 без нормализации. UTF-8 byte ranges вычисляются отдельно из неизменённого текста и не принимаются от модели. Они относятся к UTF-8 encoding snapshot string, **не гарантированно к первоначальным file bytes** (BOM, decoding или newline conversion уже могли произойти до snapshot). UTF-16 offsets, grapheme indexes и encoded JSON bytes не поддерживаются. Line numbers вычисляются по LF в raw_document, 1-based, end inclusive по последнему включённому code point; это не перенос public parent line range на child. CR сохраняется как символ; CR-only line conventions не поддерживаются. Публичные line_start/line_end сохраняются как provenance, не используются вместо точного char binding.

## Reusable API и артефакты

- `prepare_packet(public_result, binding)` → model_input + client sidecar; product object не мутируется.
- `extract_quotes(raw_answer: bytes, prepared)` → отдельный extraction JSON с raw UTF-8 hash, исходными claims, точными quotes/координатами/provenance. Невалидный JSON/schema/ID/range даёт `REJECTED`, без repair, retry, частичного rescue или новых фактов. Невалидный packet блокирует подготовку через ValueError.
- `save_artifacts(directory, raw_answer, extraction)` записывает **неизменённые raw bytes** в `raw_answer.bin` и отдельный `extraction.json`; существующие пути не перезаписываются. Вызывать также при REJECTED; raw — content ответа host, транспортный raw receipt координатор сохраняет отдельно. Координатор сохраняет prepared/model messages отдельно до host call. Directory должен быть новым/выделенным; ошибка второго write может оставить первый артефакт и не должна вызывать host retry.

Extraction статус `EXTRACTED` означает только корректную адресацию и дословность. Это не семантический PASS, не sufficient evidence, не source relevance, не complete answer и не новое authority grant. Поле `semantic_entailment=INDEPENDENT_REVIEW_REQUIRED` обязательно. Reviewer независимо проверяет каждое исходное claim против цитат с условиями/отрицаниями/owner/scope, multi-document связи, все обязательные факты исходного вопроса, missing и статус ответа по неизменному oracle. Наличие source/quote, даже дословного, не доказывает entailment. Для пустого insufficient extraction нет affirmative claims, но честность отказа всё равно требует review.

## Минимальное применение координатором

На разрешённом новом публичном packet/binding подготовить вход, сохранить hashes/контракт до одной host попытки; сохранить raw независимо от валидности; выполнить extraction отдельным client этапом и передать обе версии reviewer. Q16 newline и Q46 Markdown — известные диагностические причины для такого эксперимента, не обещанный PASS и не разрешение переисполнить V2. Не сравнивать extraction quote с V2 strict-generator-quote осью как будто prompt не менялся. Этот адаптер не устраняет upstream admission/relevance gaps, не добавляет источники и не оценивает semantic entailment.
