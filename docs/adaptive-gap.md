# Local Adaptive-gap selection (experimental, OFF by default)

This extends the existing local `cross-encoder/ms-marco-MiniLM-L6-v2` selector.
There is no extra model, training, network call, hosted selector, new MCP tool,
source summary or rewriting. The original MiniLM scores all admitted groups;
only the number of top-ranked whole groups changes. Fixed Top-5 remains the
default. This is not semantic sufficiency or an absence-of-answer classifier.

## Host settings

Provision and enable MiniLM as in `minilm-sections.md`, then explicitly select:

```sh
export DOCATLAS_CONTEXT_COMPRESSION=minilm-sections-v1
export DOCATLAS_MINILM_MODEL_DIR=/absolute/private/minilm-model
export DOCATLAS_SECTION_TOP_K=5
export DOCATLAS_SECTION_SELECTION=adaptive-gap-b1-v1
```

`DOCATLAS_SECTION_SELECTION` accepts:

- `fixed` (default): existing fixed cap.
- `adaptive-gap-v1`: experimental largest gap, no buffer (B0).
- `adaptive-gap-b1-v1`: same rule plus one additional ranked group (B1), bounded
  by the same host cap and available groups.

Unsupported values fail operationally; a runtime error is never a semantic
refusal. Existing query/model memory/output limits still apply. No selected
source is silently truncated to satisfy a token budget. `question` is unchanged;
when explicitly provided, its full translation `search_question` still drives
MiniLM. This selector does not translate or infer source language.

The reduced model-text measurements also use the existing compatible-host-only
`DOCATLAS_MCP_MODEL_VIEW=1`. A host must retain `_meta` for source resolution and
exclude it from the model input. Without that integration, the full machine
packet remains larger. See `model-context-delivery.md` and
`model-context-session.md`; don't discard provenance or promise provider savings.

## Exact frozen rule

For N descending finite raw cross-encoder scores, consider
`min(N-1, ceil(0.9*N))` adjacent differences. Pick the first maximum difference.
B0 keeps that prefix; B1 adds one further group. Clamp to the configured cap and
N. A single candidate is retained. An exactly flat distribution keeps the cap;
it has no gap signal. Source groups and selected original rows remain unchanged.
Diagnostics record the policy, configured cap, raw cutoff rank, gap count and
largest difference outside the model context. No expected answers, keywords,
question-specific exceptions or fitted relevance probabilities are consulted.

This is an empirical adaptation of a gap-selection idea, NOT a reproduction
of the Adaptive-k paper: that work uses cosine similarities rather than these
uncalibrated cross-encoder logits. A large gap does not prove the lower-ranked
section unnecessary. B1 is a fixed safety margin, not a completeness guarantee.

## Live evidence and limitations

`eval/adaptive_gap_integration.py` runs the non-editable installed wheel through
real stdio MCP, real SQLite and CPU ONNX. It saves the actual model-visible JSON,
private full packets, original uncompressed baselines, rank receipts, corpus
hashes and both o200k/cl100k token counts. Gold is opened after delivery. No LLM
answers are generated by the test driver; `PROMPTS.jsonl` contains actual context
for separate final-answer evaluation. Never call evidence coverage answer accuracy.

The original V40 and a new 16-question synthetic Markdown suite are separate.
Inputs and exact source witnesses were committed before inference. The first
live B0 run preserved 11/12 full and 2/2 partial new cases, but lost the HTTP 401
rule in a question comparing 503 and 401 (N06); Top-5 kept it. This failed run
is retained (GitHub Actions 40136271952), not relabelled as accepted.

B1 was already one of the predeclared archived experiment arms. It was promoted
to a live candidate after the B0 failure; the same 16 cases are therefore now
regression/development evidence, NOT a fresh untouched acceptance set for B1.
No question, source, witness or oracle was changed. Final exact-head live results
are attached to the experiment PR. Defaults are not changed based on this study.

Limits of the evidence: synthetic fixtures are not broad natural-document
coverage; the known V40 is not an unseen benchmark; final answering-agent
behavior, independent cold sessions and actual provider/cache billing require
separate measurement. Negative strict-empty behavior remains unresolved.

## Reproduce

Build the image in `.github/workflows/adaptive-gap-live.yml`, including both
tokenizer caches before disabling networking. Run each arm in a separate CPU
container with `--network none --cpus=2 --memory=1000000000
--memory-swap=1000000000`. The runner takes `--suite v40|holdout` and
`--policy fixed|adaptive-gap-v1|adaptive-gap-b1-v1`, plus fresh `--work` and `--out`
directories, `--repo /repo` and `--model /model`. Read both `SUMMARY.json` quality
fields and source checks: successful execution alone is not quality acceptance.
