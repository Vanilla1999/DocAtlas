# P2.1B — gold-patch and oracle positive controls

Status: **execution complete; task validity not yet established**.

## Question

Before comparing evidence conditions, can the task itself support a causal product claim?

A task is valid only when both preregistered controls pass:

1. the same reviewed gold patch applies and passes public, hidden, semantic/compile, patch-surface and oracle-isolation gates in two independent clean workspaces;
2. a real model solves the task from the minimal oracle-evidence packet under the same coding tools and hard budgets used by the comparative cells.

Provider-free replay, a gold patch alone, or the mere presence of an oracle context cannot replace the second control.

## Safety and reproducibility

The runner:

- reuses the reviewed task-level materializer, gold patches, hidden tests and evaluation contracts;
- creates two separate temporary Git repositories per task;
- restores repository validation files after each attempt;
- records only bounded hashes and gate outcomes, never hidden-test or oracle contents;
- requires request-bound real-model evidence with exact tool and budget equality;
- fails closed if task validity, gold reproducibility or pack readiness is hidden or invented.

No production runtime, public MCP schema, support rule or maturity claim changes in this slice. Product maturity remains **Beta** and Product Truth remains **not proven**.
