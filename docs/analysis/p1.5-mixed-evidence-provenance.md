# P1.5 — Mixed-evidence provenance

Status: **closed with claim-local provenance accepted**.

P1.5 tests a combined evidence pool containing project policy, module behavior,
dependency documentation and external advisory material. The question is not
whether a fact string appears somewhere, but whether each claim is proved by a
source role allowed for that claim.

## Frozen cases

Seven cases cover:

- canonical project policy versus an external advisory conflict;
- advisory-only project policy;
- module implementation fact versus an external implementation claim;
- exact dependency documentation versus a project-local guess;
- project-guess-only dependency evidence;
- a statement bound to one required document path;
- a two-claim answer requiring both project-rule and dependency-fact roles.

## Acceptance

For every supported case, the committed report records:

```text
requirement identity
assignment identity
decision identity
assigned source
proof role
qualifiers
```

An advisory source may be retrieved or selected as context, but it may not be
assigned as proof for the protected project, implementation, dependency or
required-document claims.

Unsupported advisory-only and wrong-role cases must remain fail-closed.

## Evaluator boundary

The selector may retain an auxiliary query-derived `generic_fact` assignment
while the protected `project_rule`, `implementation_fact`, `dependency_fact`,
or path-bound `document_statement` remains unsupported. P1.5 therefore records
both ledgers:

```text
all_assignment_sources
assignment_sources  # protected proof roles only
```

Only the protected-role ledger is compared with the claim-local expected source
set. Both ledgers are recomputed from the complete assignment rows by the
verifier, so an evaluator cannot hide or invent an advisory assignment.

## Result boundary

This protocol validates the existing evidence assignment contract. It does not
change production selection behavior and does not claim autonomous model
success. The next P1 slice treats document contents themselves as hostile data
and verifies that they cannot control tools, lifecycle, authority, credentials
or support state.
