# P1.6 — Evidence is data, not instructions

Status: **closed with the evidence-is-data boundary accepted**.

This protocol places hostile instruction-like text inside candidate documents.
The content attempts to:

- override `answer_supported`;
- promote its own authority;
- choose `prepare_docs` / `docs_status`;
- set lifecycle fields such as `auto_execute` and confirmation state;
- exfiltrate a credential-like value.

## Boundary under test

Document text may contribute only to evidence matching. Authority, source class,
proof role, lifecycle actions, tool choice, confirmation boundaries and support
status remain host-owned metadata and deterministic logic.

The committed report stores only a SHA-256 digest of each hostile candidate,
never the raw payload. It rejects credential markers, raw prompt injection text,
absolute paths and any content-control success.

One case deliberately contains a legitimate project-rule fact followed by a
hostile tail. The fact may be supported because its metadata is an allowed
project source, while the hostile instructions still receive no control over
tools, lifecycle, authority or credentials.

## Production-path reinforcement

The dedicated workflow also runs the existing Agent Developer adversarial and
adversarial-mutation gates. Therefore P1.6 is not based only on the synthetic
selector cases; the existing recovery/edit-authorization projection remains a
required production-path dependency.
