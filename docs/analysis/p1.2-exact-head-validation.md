# P1 exact-head validation contract

P1 evidence branches are validated at the exact commit intended for
merge. Commits created by `GITHUB_TOKEN` do not recursively trigger
ordinary pull-request workflows, so a dispatchable validation surface
is part of the reviewed P1 control boundary.

The canonical workflow is:

```text
.github/workflows/p1-stack-exact-validation.yml
```

It proves in one final `p1-stack-exact` gate:

- core tests on Python 3.11, 3.12 and 3.13;
- installed Docs MCP smoke on macOS and Windows;
- advanced, recovery, Project Docs, question-surface, Agent Developer,
  adversarial and mutation gates;
- every P1 evidence gate present on the exact ref;
- zero temporary P1 carrier workflows;
- compile, module-size and diff hygiene;
- wheel and sdist build identity;
- wheel install/MCP smoke on Python 3.11, 3.12 and 3.13;
- sdist reconstruction and installer smoke.

The workflow is introduced by a separate bootstrap MR so it exists in
`main` before the serial controller dispatches it for P1.2–closure.
It validates packaging only: it never publishes to PyPI and does not
close the deferred P0 public-release rows.
