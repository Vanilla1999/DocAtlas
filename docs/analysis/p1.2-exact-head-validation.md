# P1 exact-head validation contract

P1 evidence branches are validated at the exact commit intended for merge.

The permanent validation pair is deliberately dispatchable because commits
created by `GITHUB_TOKEN` do not recursively trigger ordinary push or pull
request workflows.

`p1-exact-head-validation.yml` proves:

- core tests on Python 3.11, 3.12 and 3.13;
- installed Docs MCP smoke on macOS and Windows;
- offline advanced, recovery, Project Docs, question-surface, Agent Developer,
  adversarial and mutation gates;
- every P1 evidence gate present on the exact ref;
- zero temporary P1 carrier workflows;
- compile, module-size and diff hygiene.

`p1-exact-release-validation.yml` independently proves:

- wheel and sdist build identity;
- release manifest gate;
- wheel install/MCP smoke on Python 3.11, 3.12 and 3.13;
- sdist reconstruction and installer smoke.

For the first P1.2 MR these workflows run as ordinary pull-request checks. Once
P1.2 is in `main`, later stacked P1 branches are validated by explicit
`workflow_dispatch` on their exact branch SHA before merge.

These checks validate packaging only; they do not publish to PyPI and do not
close the deferred P0 public-release rows.
