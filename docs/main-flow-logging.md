# Логи основного потока

Подробная диагностика по умолчанию выключена. Включение не меняет формат
ответа, источники или число продуктовых запросов.

```sh
doc-atlas --trace query "OAuth tokens" --mode lexical --format json 2>trace.jsonl
doc-atlas --trace context --help
doc-atlas --trace mcp docs-serve 2>trace.jsonl
```

Глобальные `--trace` / `--no-trace` указываются **перед подкомандой**.
Они переопределяют `DOCATLAS_TRACE` на время вызова. Без флага используется
существующая настройка: только `DOCATLAS_TRACE=1` включает трассу; значение
окружения читается при загрузке модуля, поэтому задайте его до запуска процесса.

```sh
DOCATLAS_TRACE=1 doc-atlas --no-trace query "OAuth tokens" --mode lexical
```

Для MCP-клиента можно задать `DOCATLAS_TRACE=1` в окружении серверного процесса.
Диагностика идёт в **stderr**, отдельно от JSON/текстового ответа CLI и MCP stdout.
Обычные ошибки и сторонние сообщения stderr не отключаются флагом `--no-trace`.

## События и границы

- `docatlas_request_start` и `docatlas_request_end` связываются через `request_id`.
  Поля: `interface`, `operation`, `status`; завершение содержит `duration_ms`
  и `trace_incomplete`.
- Покрыты CLI `query`, `context` и публичный диспетчер Docs MCP
  (`operation=call_docs_tool_payload`). Ошибки разбора CLI до входа в callback
  не имеют lifecycle-событий.
- Существующий `docatlas_query_trace` содержит подробную диагностику проекции
  MCP и использует тот же `request_id`. Его previews могут включать данные
  документов; новые lifecycle-события не содержат текст вопроса или документов.
- `success` означает завершение границы вызова, а не достаточность найденных
  доказательств. Возвращённые статусы `error`/`failed` и исключения отмечаются
  как `error`; результат запроса остаётся источником продуктового статуса.
- Ошибка записи диагностики не должна менять ответ. Пропущенное начало
  отмечается `trace_incomplete`; при сбое завершения предпринимается запись
  `docatlas_trace_gap`. Полностью недоступный stderr не позволяет доставить
  даже сообщение о пропуске.

## Где потерян найденный фрагмент

В `docatlas_query_trace` поле
`projection_observation.returned_core_diagnostics.context_flow` сохраняет
последовательность уже выполненных преобразований контекста:

- `core.output`, `decoration.output`, `joint.output`, `query_block.output`,
  `recovery.output` — состав источников после каждого этапа;
- `recheck.input/output` и `budget.input/output` — вход и выход поздней
  проверки происхождения и ограничения полного JSON;
- `recheck.attempt` — каждая фактически выполненная попытка проверки, её
  `checkpoint`, `axis`, `reason`, тип `derivation` и исходный кандидат;
- `recheck.row` — итог по строке: сохранена или отвергнута; попытки при
  бюджетном переборе имеют отдельный префикс `budget_trial_recheck`;
- `native_restore.attempt/row` — повторная текущая проверка исходного core-окна
  после отказа необязательного преобразования: возвращено, уже покрыто
  проверенным диапазоном или отвергнуто. Сводка — `experimental_native_restore`.

`source_key`, `source_sha256`, `snippet_sha256` и `evidence_id` позволяют
сопоставлять строки. `reference_char_start/end` описывают привязанный исходный
диапазон; `visible_char_start/end` — уникальное точное вхождение выдаваемого
текста внутри него. Это разные координаты. Если вхождение нельзя однозначно
установить, лог оставляет видимый диапазон пустым и указывает причину.
Наблюдение координат само по себе не предоставляет право читать источник.

Новые события не содержат вопрос, текст документа или открытый путь к нему.
Журнал ограничен 256 событиями, 64 строками на снимок и 262144 символами
на диагностическую проверку текста. Счётчики `omitted_events`,
`source_rows_omitted`, `serialization_omitted_events` и причины недоступного
наблюдения явно показывают пределы трассы. При выключенной трассе эти снимки,
hashes и поиск вхождения не вычисляются. Ошибка collector не влияет на выдачу.

Для разбора нужно сопоставить последний этап, содержащий независимый исходный
факт, с первым этапом без него и соответствующим отказом. `outcome=accepted`
показывает прохождение конкретной проверки, а не полноту ответа на вопрос.

В экспериментальном режиме `DOCATLAS_EXPERIMENT_ADMISSION=source_valid_candidates_v1`
отказ поздней сборке больше не означает безусловное удаление допустимого
исходного окна. Возвращаются только заново проверенные core-окна текущего
вызова; совпадение source identity и проверенных координат предотвращает
дублирование. Нового поиска или вызова модели для этого нет. Финальная упаковка
пересчитывает атрибуцию, затем применяет прежний общий лимит. Во внутренних
бюджетных пробах возврат дополнительных строк отключён, чтобы проба проверяла
именно предложенный вариант. Обычный admission по умолчанию не меняется.

## Проверка

Интеграционные сценарии находятся в
`tests/test_project_context_quality_v2_protocol.py` и
`tests/test_main_flow_logging_integration.py`: реальные документы и SQLite,
публичный MCP-dispatcher и CLI subprocess, OFF/ON/OFF, независимый исходный факт,
сохранение выдачи и корреляция событий. Это не проверка установленного MCP stdio
или production-клиента. Выполнение новых проверок ожидает разрешённого CI.

Обоснование стратегии: [результат, источники и трасса](main-flow-evaluation.md).
