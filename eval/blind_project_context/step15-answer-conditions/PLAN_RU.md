# Step15: сохранение условий в конечном ответе

Дата: 2026-11-08. База: `e62fa9e357bd22731cddabe930532a4a2faecc18`.

## Вопрос и граница

Помогает ли общий способ составления ответа сохранить условия, которые уже
доставлены отвечающей модели? Не проверяем retrieval, Qwen, one-hop, MCP,
OpenCode или включение host-v1 по умолчанию. По прямому указанию владельца
интеграционные тесты не добавляются и не запускаются; unit-тесты тоже не добавляются.

Это answer-only исследование, не product acceptance. В этой среде OpenCode
отсутствует, `codex login status` сообщает `Not logged in`, обычные API credentials
для answering provider не настроены. Секреты не извлекаются, новый login не
выполняется, модель не скачивается. Используем доступные изолированные агентные
сессии без наследования диалога, без переопределения модели/effort. Это **не Terra
Low**. Точная версия answering provider, его cached/uncached usage, reasoning
tokens и денежная стоимость данным интерфейсом не предоставляются: эти поля
остаются `null`, а не заменяются числом слов или локальным токенизатором.

## Варианты, зафиксированные до генерации

1. `current`: действующая общая инструкция с внутренней сверкой черновика.
2. `rule-contract-v1`: краткий контракт полноты применимого правила, без
   обязательных заголовков, domain examples, словарей и новых вызовов.
3. `evidence-led-v1`: составление ответа от релевантных утверждений источников,
   а не проверка уже сформулированного черновика. Те же источники и один ответный
   вызов, без показа внутренних рассуждений.
4. `source-revision-v1`: отдельная свежая сессия исправляет ответ `current`
   по тем же источникам. Это диагностический двухвызовный вариант, а не
   автоматически включаемый клиентский режим. Ошибочный черновик не служит
   источником истины; эталон проверяющему не передаётся.

В product profile доступны только первые три варианта. `current` остаётся
default; исходный `common.txt`, retrieval и historical artifacts не изменяются.
Общая новая инструкция применяется одинаково к MCP и files: её возможное
улучшение нельзя приписывать исключительно поиску DocAtlas.

## Входы и порядок

- Четыре известные development-задачи Meridian: неизменные вопросы и 19 пар
  вопрос/требование из Step14. Источники берутся из сохранённых ответов
  `get_docs_context` B, без повторного Qwen. Сохраняются текст, ref, путь и строки.
  Служебная история OpenCode не воспроизводится; это не замер его полного входа.
- Четыре новые синтетические задачи с исходниками и независимыми фактами
  составляются отдельным автором, который не читает варианты инструкции и старые
  Meridian-задачи. Есть русский/английский, процедура, короткий факт и no-answer.
  Это маленький synthetic transfer diagnostic, не реальный blind benchmark.
- Восемь задач × три одношаговых варианта = 24 уникальных входа; ещё восемь
  source-revision ответов используют ровно соответствующие первые ответы current.
  Итого 32 генерации; baseline используется повторно только как зафиксированный
  первый этап revision, а не выдаётся за независимую генерацию.
- Каждый ответ получает новую сессию без parent history. Ровно одно чтение
  заранее указанного immutable input служит передачей входа; после него tools
  запрещены. Это загрузка задания, не поиск документации. Нельзя
  передавать gold, прошлые ответы (кроме явного revision), название arm или
  целевое количество фактов. Нет повторов/выбора лучшего после просмотра ответа.
  32 генерации не объявляются 32 provider requests: внутренняя оркестрация и
  загрузка задания могут включать дополнительные обращения; их usage недоступен.
- Сначала фиксируются prompts, cases, roster и hashes. Порядок одношаговых
  вариантов циклически меняется между задачами; revision выполняется после
  сохранения соответствующего baseline. Это не рандомизация provider cache.

## Оценка

Ответы публикуются в git до независимой семантической оценки. Оценщик получает
анонимные trial ID, вопрос, источники и неизменённые требования, но не arm или
prompt. Для каждого требования: full / partial / missing / contradicted с
фрагментом ответа. Проверяем также unsupported additions, корректность ссылок,
ограниченное воздержание и лишние не относящиеся к вопросу детали.

Meridian сохраняет прежнюю шкалу (включая temporal/scope и stop-duty partial).
Её пограничную релевантность отмечаем отдельно, не меняя знаменатель ради PASS.
Не складываем повторяющиеся факты в независимые статистические наблюдения.
Наличие всех gold quotes во входе подтверждает только состав входа, не качество
ответа и не работу retrieval. Словари/keyword match не оценивают семантику.

Регистрируем UTF-8 bytes и whitespace words как размеры текста, не provider
tokens. Для revision показываем оба вывода и два логических вызова, без сокрытия
стоимости черновика. Самооценка генератора не является независимым PASS.

## Решение после опыта

Нет обещания 19/19, статистической значимости, меньшей стоимости или улучшения
Terra. Положительный результат допускает только opt-in кандидата для дальнейшей
проверки. Нулевой эффект, ceiling baseline и ухудшение публикуются без подбора
новых формулировок под ответы. Для решения о default нужен отдельно разрешённый
answer-only прогон настоящей Terra и новые реальные вопросы; этот PR его не
подменяет. Пропуски доступа/метаданных остаются явными.
