## Короткий итог

Новый один переход проверен на реальных подготовленных источниках и живых
source receipts. В специальном защитном сценарии он сохранил **7 из 7**
обязательных исходных условий вместо **3 из 7** у прежней сборки, не выдал
запрещённый модуль и не пошёл рекурсивно по ссылкам.

Однако новый полный результат по четырём вопросам Meridian получить **не
удалось**. Два русских вопроса остановились в обычном поиске до участка,
где можно безопасно воспроизвести отбор. Их результат сохранён как BLOCKED.
Основной пример Transfer → Suspension поэтому не имеет нового успешного
интеграционного замера в этом окружении. Общий результат 19/19 не заявляется.

Ни Qwen, ни MiniLM, ни отвечающая модель в этих проверках не запускались.
Реальные старые scores Qwen использованы как неизменённый вход отбора; это
не новый inference и не новый конечный ответ MCP/Qwen.

### Почему два вопроса BLOCKED

Их реальные публичные пакеты содержат `operational_status=not_found`,
`reason_code=context_only`, `delivery_decision.deliverable=false`,
`context_quality.reasons=[source_unavailable]`. Пассивный callback не вызывался.
`context_tools.py` возвращает такой operational veto до native projection.

Это отличие режимов приобретения источников, а не доказанный regression
новой closure: она для этих вопросов вообще не выполнялась. В исходном Qwen
прогоне минимальный режим использовал `iter_scope_candidates` и
`mode_used=complete_scope`, без lexical/dense admission. Немодельный внешний
вызов этого диагностического runner использует обычный поиск. Оба вопроса
целиком русские, а исходные Meridian-документы английские; общих буквенных
слов у них нет. Отсутствие лексического совпадения согласуется с полученным
`not_found`. Отдельного нового retrieval-trace запуска для доказательства
точной причины не было.

Проверены исходные `step10-multidoc-gate/tasks.json` и его runner: запросы
передавали только `question`, `project_path`, `scope`. Скрытых готовых
`search_question` или `lookup_queries`, которые можно было бы восстановить,
нет. Новые переводы, словари, lookups, oracle seeds и расширение scope ради
PASS не добавлялись.

## Защитный сценарий

Это копия прежнего публичного structural fixture с небольшими заранее
согласованными source-authored дополнениями. Один явно заданный раздел
`Selected` является компонентным входом — его не выбирала модель. Проверка
не является оценкой качества модели или способом увеличить benchmark score.

| Замер внутри одинакового fixture | run-01: off → one-hop | run-02: off → one-hop |
|---|---:|---:|
| Обязательные исходные факты | 3/7 → 7/7 | 3/7 → 7/7 |
| Выданные исходные разделы | 4 → 8 | 4 → 8 |
| Байты текста источников | 577 → 900 | 706 → 1 029 |
| Токены текста источников | 148 → 218 | 182 → 252 |
| Токены реконструированного пакета | 652 → 1 190 | 692 → 1 345 |
| Явные незакрытые ссылки после one-hop | 8 | 10 |

Во втором fixture появились две дополнительные защитные ссылки, поэтому
сравнивать абсолютную стоимость run-01 и run-02 как одинаковый запрос нельзя.
Внутри каждого запуска источники и seed для off/on одинаковые.

Проверены следующие свойства:

- Прямые ссылки из выбранного собственного текста добавляют точные исходные
  разделы и вводные части предков; baseline spans не исчезают.
- Ссылка в предке не запускает новый обход. Даже прямая ссылка `Selected` на
  уже добавленный `Guide` не меняет origin предка на `linked_body`.
- Link-only navigation list не становится frontier; его цель явно остаётся
  незакрытой, а не объявляется неважной.
- Второй переход из добавленного раздела не выполняется: остаётся
  `depth_limit`. Не включённые потомки адресованного раздела также отмечены.
- Missing anchor и document-only target не приводят к выдаче всего документа.
- Прямая ссылка на существующий module-scope источник не обходит scope.
- HTML-ссылка с `condition&amp;amp;gate` находит правильный single-decoded
  anchor, а не другой double-decoded раздел. Неверный исходный факт не выдан.
- HTML href с буквальными backticks сохранён в receipt без подмены target;
  он отвергнут с `unsupported_html_attribute_syntax`.
- Публичная компактная metadata оставляет `coverage=unverified`; наличие
  найденных ссылок не превращается в сертификат полноты ответа.

В run-02 осталось 10 явно описанных зависимостей: ancestor link, missing
anchor, document-only target, excluded module, два случая невыданных
потомков, неподдержанный HTML-атрибут, navigation link, недоступный второй
источник и ссылка второго перехода. Требуемые 7 исходных фактов при этом
найдены; это не означает, что все возможные условия документа закрыты.

Поле `added_spans` в trace равно 5: оно считается относительно исходного
набора seed+ancestors, а не относительно полного старого closure. Фактический
прирост готовых строк off → on равен **4**; именно он приведён в таблице.

## Вывод по токенам и предел доказательства

В защитном сценарии run-02 добавилось **70 токенов самих источников**, но
весь реконструированный пакет вырос на **653 токена**. Существенную часть
прироста здесь составляет оформление и явное описание десяти незакрытых
ссылок. Это специально насыщенный ошибками сценарий, не оценка среднего
расхода. Тем не менее, нельзя называть новую metadata бесплатной.

Счётчик — локальный o200k для текста пакета, не provider usage и не деньги.
Полный edge trace сохранялся вне model-facing packet; при сборке использован
продуктовый `model_closure_receipt`, то есть в токенах нет искусственной выдачи
всего host trace.

Настоящий `public_packet` сохраняется отдельно от реконструированного
`structural_replay`. Проверка последних не доказывает выпуск source cursors
на новые строки, полный MCP/Qwen путь, installed/stdio integration,
сохранность фактов в конечном ответе Terra или выигрыш относительно поиска
файлов. Для live Qwen по-прежнему отсутствуют GPU capability 12.0, CUDA 12.8,
точный pinned runtime и подготовленные модельные assets. Эти ограничения не
ослаблялись и другой моделью не заменялись.
