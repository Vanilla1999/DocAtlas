## Передача заданий

Каталог моделей harness вернул `openai/gpt-6.1-terra` (GPT-6.1 Terra).
Каждый из 16 вызовов `subagent` явно задавал этот model ID, agent `general`,
без sessionID и без effort-варианта. Существующие сессии не продолжались.
Запуски выполнялись группами 3, 3, 6, затем 4 revision; внутри групп параллельно.
Все завершились `completed` с непустым финальным ответом. Повторов и выбора
лучшего ответа не было. Все session ID записаны в `answers.json`.

Единая оболочка задания (менялся только путь):

```text
Read /tmp/opencode/step15-terra-inputs/trial-NNN.txt exactly once using the read tool. That file is the complete user task and supplied evidence. Follow its instructions. Do not read any other files, use any other tools, delegate, or consult other context. After this single input load, return only the final answer to the task.
```

Текст файла — точное поле `prompt` замороженного входа, без policy/receipt/gold.
Хеши файлов передачи сверены с входами. Ответы скопированы из возвращённых
финальных сообщений без редактирования; у `.md` есть завершающий LF, который
исключён из JSON-поля `answer`. ID сессий и статус относятся к ответу инструмента.

Доступный ответ инструмента не предоставил provider request bodies, полную
трассу действий дочерней сессии, фактический effort, server-side model snapshot,
tokens/latency/billing. Поэтому явно выбранный model ID не выдаётся за независимый
аудит маршрутизации провайдера, а требование одного чтения — за проверенную
полную tool-трассу. Дочерним сессиям не передавалась история родителя; служебные
инструкции harness и проекта могли присутствовать. Gold не включался в переданный
текст, но это не проверка технического запрета доступа к репозиторию.

## Проверки артефактов

Сборка сводки выполнена публичным CLI на настоящих ответах:

```sh
python3 eval/blind_project_context/step15-answer-conditions/study.py summarize \
  --run-dir eval/blind_project_context/step15-answer-conditions/terra-small
```

`text-metrics.json` содержит 16 ответов. `integrity-checks.json` сохраняет пять
отказов на изолированных повреждённых копиях: пустой revision roster, изменённый
revision prompt, изменённый final baseline, пропущенный revision answer,
изменённая sealed baseline-копия. Во всех случаях сводка не создана. Для первых
двух повреждений локальный seal пересчитан намеренно: отказ обеспечила также
сверка с первоначальным roster и повторная сборка prompt, а не только file hash.

`artifact-checks.json` фиксирует неизменность выбранных вопросов/gold/prompts,
соответствие source hashes и исторических spans, 16 уникальных session ID,
соответствие Markdown и JSON ответов, seal пакета независимой оценки.
Новые unit/integration-тесты не добавлялись, локальные продуктовые наборы не
запускались. Это проверка исследовательских артефактов, не продукта.

Оценщик: отдельная свежая сессия `ses_e4526f6b0ffeyiJykpr52Vy8Dc`, без выбора
модели/effort; модель родительского harness — GPT-6 Astra. Переданы только
`assessment-input.json` и инструкция сохранить `assessment.json`. Соответствие
анонимных ID вариантам находится отдельно в `assessment-map.json` и оценщику
не передавалось. Исходный пакет, его hashes и необработанная оценка сохраняются.

Первое чтение пакета оценки было обрезано инструментом на строке 675; также
обрезалась длинная JSON-строка инструкции. Оценщик честно сохранил только первые
восемь оценок и отметил остальные как недоступные. Этот исходный результат
сохранён в `assessment-partial.json`. Разрешено одно продолжение той же сессии:
прочитать отдельно уже зафиксированную многострочную инструкцию и только
недоставленный хвост пакета с offset 676. Это восстановление доставки данных
оценщику, не повторная генерация ответов или выбор более благоприятной оценки.
Ответные входы имеют максимум 91 строку и 1573 символа в строке; обнаруженный
здесь форматный предел связан с объединённым пакетом оценки, не доказывает
усечение отвечающих заданий. Полной tool-трассы ответных сессий нет.
