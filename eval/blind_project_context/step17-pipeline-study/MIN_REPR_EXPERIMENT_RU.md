# Узкий опыт: минимальная стоимость представления при неизменном no_redundancy

Дата: 2026-11-13. Отбор не меняется (G = R, зафиксирован в DECISION_RU.md). Без α, без
нового отбора, без заполнения освободившегося бюджета. Меняется ТОЛЬКО представление
доставленного текста.

## Результаты офлайн-замера резерва (свежий экзамен, 12 кейсов, существующие payloads)

### 1. Резерв точного перекрытия — мал
Точное схлопывание повторяющихся предложений в контенте строк:
- no_redundancy-3000: 11984 -> 11337 tok (резерв 5.4%), точных дублей-строк: 0
- no_redundancy-6000: 16855 -> 15890 tok (резерв 5.7%)
- control-3000: 6.2%, control-6000: 6.4%
Вывод: дороговизна no_redundancy НЕ в дословных дублях. Дополнительный контент —
смысловое перекрытие (тот же факт другими словами/в других разделах). Трек α/бюджета
отдельный; здесь не трогаем.

### 2. Главное: половина тарифицируемых токенов — каркас, а не контент
no_redundancy-3000, всего доставлено 23485 tok:
- контент строк (тексты источников): 11984 tok (51%)
- каркас строк: 6435 tok (27%): на каждую из 145 строк — ev-id (~6 tok) +
  "docatlas://source/<hash>" (~15 tok) + индексы; экранирование JSON (669 переводов
  строк как \n — 805 tok)
- остальная обёртка: ~5066 tok (22%): source_groups, source_selection, notice,
  more_context, структура JSON

### 3. Протокол эксперимента (продуктовый шаг, когда будет одобрен)
1. Неизменный no_redundancy, те же 12 вопросов экзамена, тот же кэш скоров —
   меняется только сериализация доставки. ОГОВОРКА (исправлено по ревью 2026-11-13):
   раскладка входит в проверку вместимости (_delivery_fits оценивает собранное
   представление), поэтому compact меняет вместимость бюджета, и отбор на границе
   бюджета может отличаться (в живом прогоне наблюдалось 1-строчное расхождение).
   Офлайн-замер подтверждает экономию на готовых payload-ах, а НЕ идентичность отбора.
   - таблица источников один раз на файл (7 файлов) вместо URI в каждой строке;
   - короткий локальный id строки (1 токен) вместо ev-хэша;
   - текст строки как блок markdown (литеральные переносы), не JSON-строка;
   - компактные формы notice/selection/more_context.
2. Инварианты проверки: каждое уникальное предложение контента остаётся буквально;
   чекер delivery прогоняется на всех 12 кейсах, ожидаются те же 12/12 и 16/16.
3. Метрика: charged-токены до/после. Ожидание по замеру: −17…25% (каркас+обёртка
   частично сжимаемы), контент не тронут.
4. Граница доказательства: сравнение цен представлений на одних вопросах корректно;
   идентичность отбора после compact НЕ доказана (см. оговорку в п.1), сохранение
   12/12 подтверждено только живым прогоном одного кейса. Смысловую полноту на НОВЫХ
   вопросах это не измеряет — для неё нужен новый запечатанный набор.
5. Дочитывание без per-row source_uri (исправлено по ревью 2026-11-13): удаление
   построчного URI закрывает только произвольный bounded-read по URI отдельной
   строки. Публичный вход get_docs_context(source_path=…) и выданные в конверте
   read_next/more_context сохраняются компактной раскладкой без изменений —
   контракт дочитывания не теряется; легенда compact указывает модели на source_path.

## Граница экономии
После минимального представления останется ~12k tok контента против ~4.6k у контроля.
Дальнейшее удешевление — только смысловая (трек α/бюджета, требует нового набора).

## Реализация (2026-11-13, код в docmancer/docs/application/context_assembly.py)

Добавлена раскладка "compact" = grouped-table минус построчный source_uri
(внутренний handle хранилища; контракт цитирования — ref, path, строки).
decode_context восстанавливает всё, кроме source_uri; assemble_context добавляет
кандидат только после строгой проверки восстановления. Adaptive выбирает compact
автоматически как самый дешёвый; DOCATLAS_CONTEXT_ASSEMBLY=compact — явно;
grouped-table/literal — откат.

Замер uri-алиасов отклонён: uris почти уникальны на строку (145 строк), алиас-таблица
дороже инлайна (3217 > 3072 tok). Отброшено.

### Проверки
1. Офлайн, production-кодек на реальных payload-ах экзамена (decode -> encode):
   - control-3000: 11902 -> 10826 (−9.0%); control-6000: −9.2%
   - no_redundancy-3000: 23511 -> 20948 (−10.9%); no_redundancy-6000: −10.9%
2. Живой stdio MCP (T01-ru, dev, adaptive): доставлен docatlas.assembled-compact.v1,
   decode полон (61/66 строк, все ключи кроме uri); против grouped-table на том же
   кейсе: −9.1% (L0) и −12.1% (L2). Отбор совпадает; расхождение — 1 строка на
   границе бюджета (известный межпроцессный шум порядка), в compact ничего
   уникального не потеряно.

### Итог
Каркас сокращён насколько возможно без изменения контракта цитирования: ~10% счёта.
Дальнейшее удешевление — только изменение контракта (короткие ref/uri) или смысловой
трек (α/бюджет, требует нового запечатанного набора).
