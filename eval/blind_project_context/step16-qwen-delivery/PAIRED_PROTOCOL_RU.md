# Исправленный план парного сравнения (до получения валидных B-результатов)

## Причина изменения

Предыдущий B-minimal менял приобретение кандидатов и содержал дефекты
бюджетного тримминга. Его результаты исключены из доказательства качества
ранжировщика. Исторический A0 остаётся внешней контрольной точкой:
176/260 при 12000; 120/260 при 6000; 83/260 при 3000; 51/260 при 1500.

## Контролируемый контраст

- A0: неизменённые дефолтные приобретение, проверки источников, pruning,
  eligibility, группировка, MMR и бюджетный fitter.
- B-paired: тот же путь; только релевантность в priority заменяется Qwen.
  Сохранить штраф за избыточность, нормирование стоимости и tie-break.
  Это Qwen relevance + default MMR/fitter, не чистый Qwen top-k.
- Не переносить порог старой минимальной политики: он менял бы admission.
- Сведение баллов строк в группу: максимум; точные locator-сигналы сохраняются
  одинаково в обоих вариантах. Окончательная реализация и её хеш фиксируются
  до запуска, а отклонения от этого плана раскрываются.

## Обязательные условия допуска

1. Сопоставление по (corpus, case_id, budget, portion), не по case_id отдельно.
2. Зафиксировать raw checked / post-prune / eligible пулы: упорядоченные
   source identity, scope/version, hashes, точные spans и snippet hashes.
   Нормализовать лишь документированные session-specific идентификаторы;
   исходный snapshot сохранять отдельно. Проверять равенство до отбора B.
3. Пулы могут различаться между бюджетами из-за дефолтного pruning;
   равенство обязательно внутри каждой пары, а не предполагается глобально.
4. Qwen получает неизменённый исходный вопрос и проверенные документы/target.
   Gold используется лишь офлайн для оценки. Недостаток контекста или
   несовпадение target нельзя скрывать подстановкой балла родительской секции.
5. Кеш только по точному каноническому model input и pinned contract.
   При отсутствии точного входа необходим новый измеренный скоринг;
   никакой неявной лексической подстановки. Новую форму prompt документировать
   отдельно, не называть её старым калиброванным контрактом.
6. Реальные stdio MCP-вызовы для обеих ветвей. Только фактически доставленный
   текст; hash, UTF-8 bytes и o200k фиксируются из ответа, без JSON reserialization.
7. Бюджет: max(o200k_tokens, ceil(UTF-8 bytes / 4)) <= budget после окончательной
   сборки; проверить ссылки, source hashes/spans и отсутствие ложного успеха.
8. Сначала малая интеграционная проверка, затем четыре полные парные точки.
   Повторно воспроизвести A0@12000 на инструментированном пути.

## Отчётность

Стадии без достаточной трассы = unknown, не zero/not_acquired. Отдельно
учитывать cold/fresh forwards, кеш-попадания, создание кеша, прерванную работу,
wall time и сумму времени вызовов. Не объявлять warm latency стоимостью
полного вычисления с нуля. До проверки равенства пулов valid_for_comparison=false.
