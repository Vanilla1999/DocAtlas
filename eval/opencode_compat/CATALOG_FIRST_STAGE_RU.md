Поэтому ранжирование и предел ответа не изменены, доказанного общего исправления нет. Для исправления потребуются независимые публичные сценарии с обязательными фактами и конфликтующими источниками, сохраняющие исходные вопросы, и сравнение политики замены; нельзя объявлять установленную причину достаточным доказательством конкретной эвристики. Изменения не проходят за решение задачи ответа. Полный suite и реальные клиентские сессии не запускались.

Но до первого выбора штраф был нулевой, а relevance целой группы фиксирована: её начальная оценка составляла `0,333082 / sqrt(4960) ≈ 0,00473`, против `0,01463` выбранного обрывка. Код объединяет признаки соседей, делит gain на корень стоимости всей группы и раскрывает группу на отдельные окна только после неудачной проверки её вместимости. Это конкретный **перекос порядка конкуренции**, а не доказательство, что данные обрывка семантически релевантны: в его теле из исходного русского вопроса совпадает только «как». Равновесное усреднение двух query lanes и нормализация по лучшему совпадению дают этому слову ненулевой высокий вес; в окне инструкции совпадают `mcp`, `project`, `to` английского перевода. Для URL-фрагмента совпадают `a`, `do`, `specific`, для Countdown — «как». Удаление этих слов вслепую не безопасно для вопросов, действительно спрашивающих об этих литералах; семантическая достаточность не выводится из lexical score.
