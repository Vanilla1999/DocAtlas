# Каталог и исходный вопрос: первый этап

Дата: 2026-11-02. Это не полный повтор двадцати вопросов и не проверка production smoke. До изменений зафиксированы критерии: для исходного вопроса 4 требуется вернуть исходный текст с `doc-atlas install opencode --project`, корректным путём и строками источника; отдельные факты — выбор другого абсолютного пути, отсутствие автоиндексации и корректное восстановление при mismatch. Само членство в каталоге и успех доставки не считаются ответом.

## Независимые первичные источники

- Вопрос 3: установка связывает проект, но не индексирует документы — `docs/PROJECT_BINDING.md:16-23`.
- Вопрос 4: `doc-atlas install opencode --project`; при другом проекте `--project-path /absolute/prepared/corpus` — `docs/PROJECT_BINDING.md:3-14`.
- Вопрос 5: `not_prepared`/`member_store_uninitialized` означает неподготовленное хранилище, не ошибку прав; подготовка требует подтверждённого контракта, затем повтор исходного вопроса — `docs/PROJECT_BINDING.md:25-31`.
- Вопрос 6: приоритет `--config`, `./docatlas.yaml`, `~/.docatlas/docatlas.yaml`; относительные пути индекса — от файла конфигурации — `wiki/Configuration.md:3-5`.
- Вопрос 13: другой `project_path` даёт mismatch до retrieval; подключить нужный проект, не превращать подкаталог в проект и сохранять смысл scope — `docs/PROJECT_BINDING.md:42-58`.
- Вопрос 20: `context_delivery_unavailable` — ошибка доставки, не отсутствие документов; не повторять неизменённый вызов и не расширять scope, исправить доставку; при клиентском усечении проверить реально видимый результат — `docs/opencode-compact-text.md:72-88`.

Это критерии по исходным документам, а не результат новых пяти отдельных вызовов. Файлы на английском, добавлены в `docatlas.project-docs.yaml` с `documentation_languages: [en]` и явным членством project. Устаревшие публичные рекомендации в секциях jobs `wiki/Architecture.md` заменены на `docs_status(action="job"/"jobs")` и `prepare_docs(action="cancel_docs_job")`; эти действия сверены с advertised MCP-схемами. Внутренние compatibility paths не объявлены публичными инструментами.

## Before / after и трасса вопроса 4

Вопрос без изменений: «Как привязать MCP к конкретному проекту?»; перевод без изменений: `How do I bind MCP to a specific project?`. Подробнее об ограничениях сохранённого прогона — в том отчёте; уровень Terra low независимо не подтверждён.

После правок повторён тот же вызов через host MCP: `insufficient_evidence`, `no_docs_context_available`, `source_unavailable`, `project_docs_preflight`, фактов и ссылок нет. Отдельный установленный stdio `doc-atlas mcp docs-serve` с регистрацией и `DOCATLAS_TRACE=1` дал тот же результат; это не новый автономный агентский прогон. Сохранены `/tmp/opencode/docatlas-stage-stdio.json` и `/tmp/opencode/docatlas-stage-trace.jsonl` (временные артефакты). В трассе request `9206699f97164ba9b1aa6169abe6613f`: `delivery_blocked=true`, финальных sources нет, `retrieved_candidates`, `qualification_outcomes` и core diagnostics отмечены `missing`. Поэтому трасса устанавливает блокировку на preflight до наблюдаемой выдачи, но не устанавливает, был ли источник кандидатом или где он теряется внутри retrieval/selection; отсутствие наблюдения не доказательство отсутствия кандидата. Lifecycle завершён `trace_incomplete=false`, что не восполняет отсутствующую диагностику.

Для сравнимой метрики каждого возвращённого значения использован `cl100k_base` от `json.dumps(value, ensure_ascii=False, indent=2)` без завершающего перевода строки: baseline **12 255**, после правок до синхронизации значение stdio **182** токена (отказ без контекста), после синхронизации host MCP и установленный stdio каждый **12 234** токена. Это не wire-токены и не стоимость модели; меньший размер сам по себе не означает улучшения результата.

`docs_status(action="project", details=true)` после правок: 19 кандидатов, 15 indexed, 1 stale, `project_docs_preflight_confirmation_required`; риски включают stale sources, shadowed local config и dirty worktree. Эти счётчики не доказывают индексирование новых трёх файлов. Хранилище host выбрал как `~/.docatlas/mcp-members/members.db`, режим lexical; MiniLM не настроен. Изменённый `wiki/Architecture.md` также требует актуализации индекса, иначе его прежний текст не должен считаться текущим свидетельством.

## Подтверждённая синхронизация и проверка после неё

Предыдущее заключение о блокере было преждевременным: отказ вызова без `mutation` **не доказывал**, что подтверждённая синхронизация невозможна. После явного разрешения пользователя актуальные bindings получены через установленный пакет: host `member_storage_policy.db_path` и `generation()`, `read_project_docs_catalog`, `catalog_entry_hash`, SHA-256 текущих каталога и файлов. Публичный `prepare_docs(action="sync_project_docs", project_path=..., mutation=...)` через установленный stdio успешно подтвердил транзакцию для ровно четырёх рассмотренных файлов: три новых и изменённый `wiki/Architecture.md`. Результат: `committed`, generation `gen-3b3c5aded06e454e869e3836a521b1b8`, 53 секции; без vectors и без удаления других источников. Запрос и результат сохранены в `/tmp/opencode/docatlas-close-stage/mutation.json` и `sync.json`. Это локальная мутация private member store, не редактирование источников через MCP. Предыдущий отклонённый вызов с `scope` не исполнялся.

После успешной транзакции исходный вопрос 4 с тем же переводом выполнен через installed stdio с `DOCATLAS_TRACE=1`, затем один раз через host MCP. Оба результата `truncated`, 66 строк, бюджет ограничен. В конечной выдаче `docs/PROJECT_BINDING.md` присутствует только в `ev-d3d6f48a2b24c546`, строки 74–79 — это граница проверки, **не команда привязки**. Исключительно по конечному тексту критерий вопроса 4 — **FAIL**: ни `doc-atlas install opencode --project`, ни нужные строки 3–14 не доставлены. Прямой независимый исходный файл содержит обе команды в строках 3–14. Наличие файла не является доказательством успешного ответа.

Разбор installed stdio trace `/tmp/opencode/docatlas-close-stage/trace.jsonl`, request `5de6bb57c65d4be397bf25f069963e97` (результат — `question04.json` в той же директории):

- Preview retrieved candidates содержит 16 элементов; искомого файла среди них нет, но полнота upstream preview не установлена. Это не доказывает, что документ не был кандидатом.
- В `core.output` зафиксировано 281 строка, но снимок показывает только 64, остальные 217 опущены. Три видимые строки того же файла не содержат команду. Отсутствие команды в этом снимке не доказывает отсутствия в полном core.
- Конкретное окно с командой подтверждается на `recheck.attempt` sequence 132 и `recheck.row` sequence 133: `ev-ff5678be8ee1fba5`, `docs/PROJECT_BINDING.md:1-15`, source SHA-256 `b1823bad5e2f19f23cf826df0c6b53cf9d436008e942826bf0ea1d002d06582e`, точное видимое вхождение `[0,357)`, результат `accepted` / `retained`, причина `source_valid_unassessed`. Факт наличия команды в этом диапазоне проверен по первичному файлу, а не выведен из статуса проверки.
- В конечной выдаче этого `ev-ff5678be8ee1fba5` и команды нет. Публичная сводка отбора сообщает 281 candidate, 279 eligible, 66 selected, 215 omitted, `budget_limited=true`; это не объясняет индивидуальный отказ. Из 566 событий записаны 256, опущены 310; границы joint и budget в записи не наблюдаются. Следовательно подтверждённый интервал потери — **после принятого recheck и до итоговой выдачи**; точно выбрать joint, budget или другую промежуточную стадию нельзя. `trace_incomplete=false` lifecycle не отменяет этого явного лимита событий.

Это проверка конкретной выдачи, не доказательство отсутствия устаревших рекомендаций во всех документах.

Итог: пункты об исправлении подтверждённых job-рекомендаций и исследовании исходной трассы выполнены; **поиск для вопроса 4 остаётся неисправленным**.
